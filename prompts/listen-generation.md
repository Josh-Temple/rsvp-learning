# Listen HTML 生成用プロンプト

以下のニュース、調査結果、レポート、資料要約、作業結果またはメモを、Android Chromeで連続して聞くためのListen HTMLへ再構成してください。

上位仕様:

- Project Source「Listen / Learn HTML 生成ルール v0.1」
- `docs/LISTEN_HTML_FORMAT.md`

## 内容

- 元資料にない事実を補完しないでください。
- 不明な点は不明のまま扱ってください。
- 事実、解釈、推測、不確実性を区別してください。
- 現在性が重要な場合は必要な確認を行ってください。
- 長い原文を転載せず、耳で理解できる独自の説明へ再構成してください。
- 重要な根拠、条件、限界を落とさないでください。

## 構成

内容に応じて次の流れを優先してください。

1. 今回扱う内容と聞く価値
2. 何が起きたか・何が分かったか
3. 背景
4. 意味や影響
5. 条件・限界・未確認点
6. 最後に残す要点

複数テーマがある場合は、冒頭に短い見取り図を置いてください。

テーマが切り替わるときは「次に」「一方で」「ここからは」など、音声だけで区切りが分かる接続表現を使ってください。

## 文体

- 自然な日本語の書き言葉
- 一文を過度に長くしない
- 画面位置へ依存しない
- 表や複雑な箇条書きに依存しない
- ポッドキャスト風の挨拶、相槌、架空の会話を追加しない
- 生URLを本文へ置かない
- 読み方が曖昧な略語は必要に応じて読みやすくする

## HTML

本文と読み上げプレイヤーは独立したHTMLに収めます。画面遷移は既存の共通部品を読み込みます。`listen/research/`、`listen/reports/` の各記事では `../article-nav.css` と `../article-nav.js` を `head` から読み込み、`.topbar .mode-nav` のモードリンクをRSVP・Learn・Listenの順で置いてください。共通部品により文字ラベルと「← Listen一覧へ」が表示されます。

必須:

- UTF-8
- `lang="ja"`
- `main` / `article`
- 本文は初期HTML内の通常テキスト
- 見出しは `h1`〜`h3`
- 本文は `p`
- 外部フレームワークや外部フォントを必須にしない

## 読み上げプレイヤー

Chrome標準読み上げには依存せず、Web Speech APIを実装してください。

- 再生
- 一時停止
- 停止
- 日本語音声選択
- 0.7〜4.0倍速
- `article` 内の `h1, h2, p` をDOM順に読み上げ
- 見出し・段落単位で `SpeechSynthesisUtterance` を作る
- 現在の要素をハイライト
- ページ離脱時にcancel

バックグラウンド再生を保証しないでください。

## メタデータ

時間依存情報では、本文冒頭または視覚上分かる場所に情報基準日を残してください。

ファイル名には原則として `YYYY-MM-DD` を含めてください。

## 一覧登録

完成後、`listen/index.json` の `items` に追加してください。

必要フィールド:

- `id`
- `title`
- `date`
- `category`
- `path`

categoryは原則 `news`, `research`, `report`, `note` のいずれかです。

既存項目を壊さず、日付降順で表示できるデータにしてください。

## 出力前確認

- 音声だけで内容を追える
- 情報基準日が分かる
- 事実と分析を混同していない
- 条件・限界・未確認点を保持している
- 生URLが本文にない
- 0.7〜4.0倍速になっている
- 一覧登録まで完了している

リポジトリへ書き込める場合、コードブロックだけで終わらずHTMLファイルと一覧更新まで実行してください。
