# Learn HTML 生成用プロンプト

以下の指示は、レビュー済み教材原稿または根拠資料から、このリポジトリ用のLearn HTMLを生成するときのテンプレートです。

上位仕様:

- Project Source「Listen / Learn HTML 生成ルール v0.1」
- `docs/LEARN_HTML_FORMAT.md`

実装例:

- `learn/api-authentication-authorization.html`

---

`COMPLETE v0.1` の完成済みMarkdown教材を主入力として、Android Chromeで連続して耳から学べるLearn版へ再構成してください。出力は教材ごとの静的HTMLです。

## 内容の扱い

- 入力が `COMPLETE v0.1` でない教材からLearn HTMLを生成しないでください。
- Learn本文は完成済みMarkdownから再構成し、RSVP JSONチャンクの単純連結を使わないでください。

- 元資料がある場合、元資料にない事実を補完しないでください。
- 不明な点は推測で埋めないでください。
- 事実、解釈、推測、不確実性を区別してください。
- 現在性が重要な内容は、必要な場合だけ最新情報を確認してください。
- 元資料の長い文章を転載せず、独自の説明文へ再構成してください。
- 重要な条件、例外、限界を落とさないでください。
- RSVP JSONの短いチャンクを単純連結して本文にしないでください。

## Learn向け再構成

最初に、何を学ぶのかと主要概念の関係を短く示してください。

内容に合う範囲で、次の順序を優先してください。

1. 概念・定義
2. 具体例
3. 似た概念との違い・関係
4. 実際の場面での使われ方
5. 短い再整理

一度に多数の新概念を投入しないでください。

抽象概念には必要に応じて具体例を付けてください。

重要概念は後の例、比較、応用場面でも自然に再登場させてください。同じ文章の単純な反復は避けてください。

## 逐語的な再掲の禁止と内容保持

Markdownの番号付き本文を、Learn末尾に一項目ずつ段落として再掲しないでください。講義の内容を薄くして短くするのでもありません。学習者が仕組み、原因、具体例、限界、検証手段を追える連続文章に再構成し、最後は少数の自然な文で振り返ってください。

生成・改稿前に、Markdownの学習目標、主な概念、対比、例外・反例、具体例、検証方法、出典を確認してください。生成後はこれらが本文に残るかを点検し、本文項目の逐語的コピーではなく、意味の対応表を記録してください。架空の状況例はその旨を明示し、実例のように書かないでください。専門語の原語は保持し、TTS発音に必要なら初出時のみ読みを補ってください。

## 読み上げ文章

- 自然な日本語の書き言葉にしてください。
- 英語直訳調を避けてください。
- 一文を過度に長くしないでください。
- 主語、対象、因果関係が音声だけでも追える文章にしてください。
- 表、複雑な箇条書き、脚注記号、注釈番号へ依存しないでください。
- 「上記」「下表」「右図」など画面位置依存の表現を使わないでください。
- ポッドキャスト風の挨拶、相槌、架空の司会者同士の会話を追加しないでください。
- 意図的な沈黙、回答待ち、手動操作、ノート記入を要求しないでください。
- 問いかけを使う場合は、そのまま答えまで続けてください。

## 略語・専門用語

専門用語は初出時に必要最小限の説明を付けてください。

TTSで読み方が曖昧になりやすい英字略語は、必要に応じて最初だけ読み方を添えてください。

例:

- 「オーオース、英字では OAuth」
- 「エーピーアイキー、英字では API Key」

読み方を確定できない語を推測しないでください。

## HTML

教材ごとのHTMLに本文を初期DOMの通常テキストとして含めてください。共通CSSと読み上げJavaScriptは `learn/learn.css` と `learn/learn.js` に置き、各HTMLから相対参照してください。

必須条件:

- UTF-8
- `<html lang="ja">`
- viewport指定
- 適切な `title` と短い `description`
- `main` と `article` を中心に構成
- 見出しは `h1`〜`h3`
- 本文は `p`
- 読み上げ本文を初期HTML内の通常テキストとして保持
- 外部フレームワークを必須にしない
- 外部フォントを必須にしない
- CSSは最小限
- ナビゲーションや補助UIを増やしすぎない

## ページ内読み上げ

Chrome標準の「このページを読み上げ」へ依存しないでください。

`window.speechSynthesis` と `SpeechSynthesisUtterance` を使ったページ内読み上げを実装してください。

現在の仕様:

- `article` 内の `h1, h2, h3, p` をDOM順に読み上げる
- 一つの巨大なutteranceにせず、見出し・段落単位で発話する
- 再生ボタン
- 一時停止ボタン
- 停止ボタン
- 利用可能な日本語音声の選択
- 音声選択を変更した場合、現在位置から読み直す。再生中はその場で切り替え、一時停止中は一時停止状態を保ち、再生ボタンを押したときに新しい音声で現在位置から読み直す
- 0.7〜4.0倍の速度調整
- 現在読み上げ中の見出しまたは段落をハイライト
- 現在位置へ穏やかにスクロール
- ページ離脱時に読み上げを停止

最低限 `idle`、`playing`、`paused` の状態を扱ってください。

停止時は読み上げをキャンセルし、先頭へ戻してください。

`canceled` と `interrupted` は通常の操作でも起こるため、致命的エラー表示にしないでください。

Android Chromeでは、Chromeを前面から外すと読み上げが止まることがあります。バックグラウンド再生を保証するUI文言や説明を入れないでください。

## 出典

出典が必要な教材では、本文の後に出典セクションを置いてください。

- 本文中に生URLを表示しない
- リンク文字列には資料名や媒体名を使う
- 元資料にない出典を追加しない

出典を読み上げたくない場合は、視覚上は残したまま読み上げ対象の `article` 外に置いて構いません。

## デザイン

本文が主役です。

- 広い余白
- 強い見出し階層
- 濃紺系の本文
- オフホワイト系の背景
- くすんだアクセント
- カードUIを多用しない
- 操作UIはコンパクト

既存のLearnページと視覚的な一貫性を保ってください。

## 出力前の検証

HTMLを生成したら、次を自己確認してください。

1. 初期DOMに本文が存在するか
2. 音声だけで本文を理解できるか
3. 強制ポーズや回答待ちがないか
4. 画面位置依存の表現がないか
5. 英字略語が不自然な読みになりそうではないか
6. 生URLが本文にないか
7. 再生・一時停止・停止が実装されているか
8. 日本語音声選択があるか
9. 速度上限が4.0倍になっているか
10. 段落単位の読み上げとハイライトがあるか
11. バックグラウンド再生を保証していないか

問題があれば、推測で内容を変えずに修正してください。

## 出力

リポジトリへ書き込める環境では、完成した `.html` ファイルとして保存してください。

コードブロックだけを最終成果物にしないでください。

既存教材に対応する場合は、教材IDと対応が追えるファイル名を使ってください。
