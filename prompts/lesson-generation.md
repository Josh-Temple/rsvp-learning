# RSVP教材JSON変換用プロンプト

以下の指示は、レビュー済みの学習教材原稿を RSVP 用教材JSONへ変換するときのテンプレートです。

---

与えられたレビュー済み教材原稿を、RSVPで学習するための短い意味単位へ分割してください。

完成statusと完成条件は `docs/LESSON_FORMAT.md` に従います。本文を変更した場合は、MarkdownとJSONの本文連結・出典を同期し、validationが通るまで `COMPLETE v0.1` にしないでください。

この工程では、教材の論旨や事実関係を勝手に変更しないでください。内容上の問題を見つけた場合は推測で修正せず、JSON化を止めて問題点を示してください。

目的は、原稿をそのまま高速表示することではなく、意味を保ったまま、一度に把握しやすい単位へ整えることです。

## RSVP向け分割

- 1チャンクにつき、原則として1つの意味のまとまりにしてください。
- 文字数より自然な意味単位を優先してください。
- 目安として4〜14文字程度を中心にし、固有名詞や専門用語では必要に応じて長くしてください。
- 助詞だけを独立させないでください。
- 「例えば」「一方」など短い接続語は、単独にする必要がなければ次の内容とまとめてください。
- 固有名詞、数値、専門用語を不自然に分割しないでください。
- 前のチャンクを見返さなくても流れを追いやすい語順を保ってください。
- 内容を省略する場合は、重複表現に限ってください。重要な条件、例外、限界は残してください。

## 表示時間

- 通常チャンクは `duration_multiplier: 1.0` を基準にしてください。
- 短く予測しやすい部分は 0.8〜0.9 程度にできます。
- 文末、話題転換、重要概念は 1.2〜1.5 程度にしてください。
- 難しい数値、固有名詞、専門用語は必要に応じて長くしてください。

## 出典

- 原稿に出典がある場合は `sources` に引き継いでください。
- 原稿にない出典を推測で追加しないでください。

## 出力

`schema/lesson.schema.json` に適合するJSONだけを出力してください。

```json
{
  "schema_version": 1,
  "id": "kebab-case-id",
  "title": "教材タイトル",
  "topic": "分野",
  "summary": "教材の内容を1文で説明",
  "created_at": "YYYY-MM-DD",
  "base_duration_ms": 650,
  "sources": [],
  "chunks": [
    {
      "text": "短い意味のまとまり",
      "duration_multiplier": 1.0
    }
  ]
}
```
