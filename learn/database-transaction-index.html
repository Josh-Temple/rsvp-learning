トランザクションとインデックス

この章では、データ更新の整合性を守るトランザクションと、検索性能を支えるインデックスの基本を学びます。

具体例で確かめる

口座AからBへ送金するとき、Aから引いた後で処理が失敗し、Bへ足されないままでは困ります。二つの更新を一つの取引として扱い、失敗時はまとめて戻します。

更新を一まとまりにする

トランザクションは、複数の処理を一まとまりとして扱います。途中で失敗した場合、処理を取り消すことがあります。これをrollbackと呼びます。すべて成功したら、変更を確定します。

ACIDの四つの性質

これをcommitと呼びます。AシーアイDは、トランザクションの代表的な性質を表します。Atomicityは、処理を全部成功か全部失敗にします。

索引が助ける検索

送金の二つの更新を一緒に確定すれば、途中失敗で片方だけが残る状態を避けられます。Consistencyは、整合性を保つことに関係します。Isolationは、同時実行の影響を制御します。Durabilityは、確定した結果を保持する性質です。インデックスは、検索を高速化するための構造です。

整合性と性能を分ける

ただし、インデックスにも保存容量と更新コストがあります。すべての列へ付ければ良いわけではありません。整合性と性能は、用途に応じて設計します。

別の例として、注文IDで一件を頻繁に探すなら索引が役立ちます。索引は読み取りを助ける一方、書込み時の更新と保存領域を要します。取引と索引は異なる問題を解きます。索引は検索のための仕組みなので、送金の整合性を保証するトランザクションとは役割が違います。

別の条件で確かめる

同じ口座へ二人が同時に入金します。双方が古い残高を基に上書きすると一方が消えます。同時更新をどう隔離するか決めます。

索引を増やせばこの問題を防げますか。検索性能と更新の整合性は別です。
