トランザクションとインデックス

データ更新の整合性を守るトランザクションと、検索性能を支えるインデックスの基本を学びます。

更新を一まとまりにする

口座AからBへ送金するとき、Aから引いた直後に処理が止まり、Bへ加算されなければ整合性が崩れます。複数の更新を一つのトランザクションとして扱い、失敗時はまとめて戻し、成功時はまとめて確定します。

ACIDと同時実行

Atomicityは途中だけ残る状態を避けます。Consistencyは制約や処理規則とともに整合した状態を保つことに関係します。Isolationは複数の取引が同時に動くときの見え方を扱い、Durabilityは確定した結果を保持する性質です。

同じ口座へ二人が同時に入金し、双方が古い残高を基に更新すると、一方の変更が失われることがあります。隔離の強さを上げればすべて解決するわけではなく、待ち時間や競合との兼ね合いもあります。

インデックスは別の問題を解く

インデックスは注文IDのような検索を速くするための構造です。一方で、更新時には索引自体も維持する必要があり、保存領域も使います。すべての列へ機械的に付けるのではなく、検索条件や利用頻度を見て判断します。

重要なのは、索引は検索性能の仕組みであり、同時更新の整合性を保証する仕組みではないことです。トランザクションとインデックスは同じデータベース機能でも解く問題が違います。

症状から原因を分ける

検索が遅いなら、どの条件で検索しているかや実行計画、索引の有無を確認します。同時更新で値が失われるなら、トランザクションや競合制御を確認します。索引を増やせば競合を防げるか、という問いには「別の問題なので、それだけでは防げない」と答えられます。
