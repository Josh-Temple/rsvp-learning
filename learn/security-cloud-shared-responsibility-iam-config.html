Cloud責任分界・IAM・設定

Cloudを安全な場所として一括りにせず、Service modelごとの責任分界、IAM、Network、Data、Logging、Configuration、Multi-account設計を学びます。

Cloudでも利用者責任は消えない

Cloud providerはPhysical infrastructureやManaged serviceの一部を保護しますが、利用組織のIdentity、Data、Configuration、Access policyなど多くの責任は残ります。IaaS、PaaS、SaaSで境界が変わるため、契約と公式責任モデルを確認します。

同じProviderでもServiceごとに責任範囲は異なります。

IAMを中心に設計する

CloudではHuman identityだけでなくWorkload identityも多く使われます。Root権限の日常利用を避け、Role、MFA、短命Credentialを使い、不要なAccess keyやIdentityを削除します。

Control planeへの強い権限は影響が大きいため、通常業務から分離します。

Misconfigurationを継続的に検出する

Storage公開、Security group、Network route、外部共有などの設定ミスは重大なExposureにつながります。Infrastructure as CodeやPolicy as Code、Guardrailを使う場合も、ReviewとRuntimeのdrift監視を組み合わせます。

Public exposureを資産Inventoryと連動して把握します。

LoggingとAccount分離を設計する

Control plane log、Data access logなど必要なTelemetryを有効にし、攻撃者が簡単に削除できない場所へ保管します。Multi-account構成は環境や権限の分離にも利用できます。

Log保持、Break glass、監査Accountなど運用面まで設計します。

SaaSも設定と連携がAttack surface

SaaSではServer管理をProviderへ任せても、Sharing、External app連携、Identity、Data retention、Audit logなどは利用組織が管理します。

ProviderやServiceの機能変更も追跡し、責任分界とCloud postureを継続的に見直します。
