Tool CallingとAgent

この章では、エルエルエムが外部ツールを使う仕組みと、複数ステップを進めるAgentの設計上の注意点を学びます。

具体例で確かめる

AIが申請状況を調べ、必要なら担当者へ通知するとします。検索は読み取りですが、通知は外部へ作用する操作です。

ツールの呼び出し

エルエルエムは、文章を生成するだけでなく外部機能を呼び出せます。これを、Tool Callingとして扱います。例えば、検索、計算、データ取得をツールへ任せられます。モデルは、用意されたツールの中から、呼び出すツール名と引数を応答として返します。

実行するのはアプリ

実際の処理は、呼び出し側のアプリがツール名と引数を確認して実行します。ツールの結果を、再びエルエルエムへ返します。Agentでは、この判断と実行を複数回繰り返すことがあります。

複数段階の失敗

通知の前に検索結果を読めても、その情報を誰へ送ってよいかは別の判断です。複雑な仕事を、複数ステップへ分けられます。一方で、実行回数が増えるほど失敗経路も増えます。書込みや送信などの副作用には特に注意します。権限を必要最小限にします。

副作用と権限

重要な操作前に、人間承認を置くことがあります。途中状態と実行履歴を記録すると復旧しやすくなります。Agentは、自律性より制御可能性を含めて設計します。

AIが選んだ宛先と内容を、送信前に権限と対象案件で検査します。応答が遅くても、同じ通知を無条件に再送すると重複するかもしれません。各呼出しの入力と結果を記録し、失敗後に何を再試行できるか決めます。再試行では検索と通知を同じように扱わず、重複や外部への作用を確認します。

別の条件で確かめる

検索結果が正しくても、宛先が別部署だとします。通知という外部操作の前に止める必要があります。宛先と対象案件の権限を照合します。

検索が成功すれば送信してよいですか。送信の条件を独立に検証します。

外部作用には独立した安全条件を置く

Tool Callingでは、検索のような読み取りと、送信や更新のような外部作用を分けます。モデルが正しい判断をしたように見えても、ツールへ渡す引数や対象の権限を独立して検証します。

実行APIが成功を返しても、期待した対象が実際に変更されたかは読み戻して確認します。複数ツールを連鎖させるAgentでは、回数や費用の上限、失敗時の停止条件を決めます。
