データ分類・暗号化・保持・廃棄

Data lifecycleを生成、利用、共有、保存、Backup、Archive、廃棄まで追い、分類に応じてAccess、Encryption、Retentionを変える考え方を学びます。

Data lifecycleを追う

Dataは保存場所だけを見ても管理できません。生成、利用、共有、保存、Backup、Archive、廃棄までどこへ移動するかを追います。所有者と利用目的を明確にし、Data flowを把握します。

新しい連携や外部Serviceが増えればData flowも更新します。

分類を取扱規則へつなげる

Sensitivityに応じて公開可能、内部限定、機密などの分類を設ける場合があります。重要なのはLabelを付けることではなく、Access、共有、Encryption、Retentionなど具体的な取扱規則へつなげることです。

分類体系は組織の業務と法的要求に合わせます。

通信中と保存中を分けて守る

通信中のDataにはTLSなど、保存中のDataにはStorage encryptionやApplication level encryptionなど、場所と脅威に応じた保護を選びます。

暗号化していても過剰権限があれば正規経路からDataを読まれるため、Access controlと鍵管理を組み合わせます。

集め過ぎと複製し過ぎを減らす

Data minimizationは、必要のないDataを最初から持たないことで攻撃時の影響を減らします。Test環境へのCopy、分析用の複製、個人端末へのDownloadなど、二次利用で保護が弱くなる場所を確認します。

MaskingやTokenizationを使う場合も、目的と残る再識別リスクを評価します。

Retentionと廃棄を設計する

Dataには業務、法令、契約上の保存理由がありますが、理由なく永久保存すると侵害時の影響を増やします。保存期限、Legal hold、削除手順を区別します。

Replica、Backup、Archiveまで含めて削除や残存を管理し、必要に応じてCryptographic erasureなども検討します。

短い振り返り

データは保存場所だけでなく、生成から共有、バックアップ、保管、廃棄までの流れで把握します。機密性などに応じた分類を付ける目的はラベルを増やすことではなく、利用権限、共有条件、暗号化、保存期間といった取扱いを決めることです。分類は業務や法的要求と整合させます。

通信中の保護と保存中の保護は別に考えます。暗号化しても正規の権限が広すぎればデータを読まれ得るため、認可と鍵管理も必要です。複製やテスト環境への持出しを減らし、マスキングなどを使う場合も再識別の可能性を評価します。

必要な保存と理由のない永久保存を区別し、法的な保持条件や削除手順を確認します。通常の保管先だけでなく複製、バックアップ、アーカイブに残るデータも追跡します。

この教材の扱う範囲

法定保存期間や個人情報の具体的要件はData種別と法域で異なります。対象法令・契約・業界基準を個別に確認します。
