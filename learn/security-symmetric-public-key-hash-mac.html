共通鍵・公開鍵・ハッシュ・MAC

暗号の主要なPrimitiveを、機密性、完全性、真正性という目的から区別し、組み合わせ方と限界を学びます。

暗号Primitiveを目的で分ける

暗号技術には、機密性、完全性、真正性など異なる目的があります。共通鍵暗号、公開鍵暗号、Hash、MACを一つの「暗号」としてまとめると、何を守れていないかを見落とします。

最初に必要なSecurity propertyを明確にし、それに合うPrimitiveを選びます。

共通鍵と公開鍵を組み合わせる

共通鍵暗号は同じ秘密鍵で暗号化と復号を行い、大量のDataを効率的に処理しやすい一方、安全に鍵を共有する課題があります。公開鍵暗号は公開鍵と秘密鍵を使い、鍵共有や署名など別の役割を持ちます。

実際のProtocolでは両者を組み合わせるHybrid方式が広く使われます。

HashとMACを区別する

Hashは入力から固定的なDigestを作り、変更検知などに使えますが、秘密を使わないためHash値だけで送信者を証明できません。攻撃者も同じHash計算を実行できるからです。

MACは共有秘密を使ってMessageの完全性と秘密を持つ主体からの生成を確認します。

認証付き暗号とNonce管理

暗号化しただけでは改ざん検知が十分とは限りません。現代の設計では機密性と完全性を組み合わせる認証付き暗号が利用されます。

方式によってNonceやIVの再利用が重大な問題になるため、暗号Libraryが求める生成と管理規則に従い、独自設計を避けます。

暗号はSystem全体の一部

強いAlgorithmでも鍵が漏れれば意味を失います。暗号化しても認可、Endpoint防御、Backup、監視は必要です。

Algorithmの危殆化や標準変更へ備え、Crypto agility、鍵の所在、Data format、依存Libraryまで把握して移行可能な構成にします。
