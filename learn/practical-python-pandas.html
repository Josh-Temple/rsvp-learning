Python・pandasによる探索と集計

pandasで入力・集計・結合の前後を確認し、欠損や重複に注意します。

Pythonのpandasは、表形式のデータを扱うためのライブラリです。操作名を覚えることより、どの行が何を表し、処理の前後で何が変わるかを説明できることが重要です。ここでは架空の問い合わせ記録を、部署ごとに数える例を使います。

入力の意味と型を確かめる

一行が問い合わせ一件を表す表に、受付ID、部署、受付日、処理時間が入っています。読み込んだら、総行数、受付IDの重複、部署と処理時間の欠損、日付として読めない値を確認します。日付が文字列のままだと、日付順の並べ替えや期間の抽出を誤ることがあります。受付IDは数字に見えても、足し算する数量ではありません。

次に、対象期間と対象部署を明示して行を選びます。対象外を落とした件数を控え、処理時間が記録された行だけを使うのか、全問い合わせ件数を使うのかを分けます。加工前の表を書き換えず、入力データの版と変換規則を残します。

groupbyの欠損キーに注意する

部署A二件、部署B一件、部署未記入一件の計四件があるとします。pandasのgroupby('部署') は、既定の dropna=True では、部署が欠損した行をグループのキーとして表示しません。その結果、部署別の件数を足して三件となっても、原データの四件と一致しません。

欠損部署も一群として示したいなら groupby('部署', dropna=False) を検討します。ただし、「未記入」を正式な部署へ割り当てたことにはなりません。未記入の一件がどこに属するかは不明です。利用者が知りたいのが問い合わせ総数なら、部署別内訳の欠損群を含めて読みます。

この行が返すのはグループ別の行数です。count() は対象列のNULLの扱いによって結果が違うため、目的に合わせて選びます。

mergeで表が増える場合

問い合わせ一件の表に、対応履歴を結び付けると、一つの問い合わせに複数の対応がある場合に行が増えます。pandasの merge には validate='one_to_one' や validate='one_to_many' などの指定があり、キーの一意性について期待を検査できます。indicator=True なら左だけ、右だけ、両方にある行を区別できます。検査を通過しても、対応履歴の内容が現実を正しく表すとは限りません。

さらに、pandasのmergeは、左右の結合キーがともに欠損している行を一致させることがあります。通常のSQLでNULL同士を等号で結合する場合とは異なるため、欠損キーを事前に数え、同一対象を意味すると考えてよいかを検討します。必要なら欠損キーの行を別に扱い、結合しなかった件数も残します。

結果を保存する際は、入力の版、ライブラリの版、処理内容、行数の変化、欠損の扱いを一緒に記録します。複雑な処理を一行で書くより、途中結果を再計算できることが品質の基礎です。pandasは分析を助けますが、問いと分母を正しく定義する作業までは代行しません。

画面で確認する実行例

import pandas as pd

df = pd.DataFrame({
    "受付ID": [1, 2, 3, 4],
    "部署": ["A", "A", "B", None],
})
counts = df.groupby("部署", dropna=False).size()
print("入力行数:", len(df))
print("集計行数の合計:", int(counts.sum()))
print("部署未記入:", int(counts[counts.index.isna()].iloc[0]))
入力行数: 4
集計行数の合計: 4
部署未記入: 1
