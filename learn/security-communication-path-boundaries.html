通信経路とセキュリティ境界

利用者からServiceまでの通信経路を名前解決、接続、Gateway、Application、外部依存へ分解し、どこで信頼条件が変わるかを学びます。

通信をData flowとして見る

利用者からApplicationまでの通信には、名前解決、Routing、Gateway、Proxy、Load balancer、CDNなど複数の要素が関わる場合があります。さらにApplicationからDatabaseや外部APIへ通信が続きます。

機器の名前だけでなく、送信元、送信先、Protocol、Port、Data種別、認証情報の流れを整理します。

信頼境界はInternetだけではない

信頼条件が変わる場所を境界として考えます。利用者とService、Service同士、Cloud account、管理面とData面など、組織内部にも境界があります。

Zero Trustの考え方では、Network上の場所だけを理由に資源を暗黙に信頼しません。

保護と観測を同じ経路へ置く

暗号化、認証、認可が必要な場所をData flow上で決めます。同時にDNS、Proxy、Firewall、Application、Cloud auditなど、異常を観測できる点を設計します。

Logを大量に集めるだけでなく、どのSecurity判断に使うかを明確にします。

正常経路だけでなく失敗経路を見る

DNS、Identity、Gateway、外部APIなどの障害時に、利用者や運用者が安全対策を迂回する経路を作らないようにします。非常用経路にも認証、記録、期限を設けます。

構成変更後は図だけでなく、実際の通信と設定を確認します。
