REST APIとJSON

この章では、REST エーピーアイの基本的な考え方と、データ交換形式ジェイソンの読み方を学びます。

具体例で確かめる

申請一覧を取得する要求を送ると、サーバーはJSONで申請IDと状態を返すとします。新規作成では必要な項目を送信し、成功時は作られた資源を示します。

資源とHTTPの操作

エーピーアイは、ソフトウェア同士の接点です。RESTは、Web エーピーアイで広く使われる設計上の考え方です。資源を、ユーアールエルで表すことがあります。エイチティーティーピーメソッドで、操作の種類を表します。

RESTの原則

例えば、顧客一覧をGETで取得できます。新しい顧客をPOSTで登録する設計もあります。ユーアールエルとエイチティーティーピーメソッドを使うだけで、RESTの原則をすべて満たすとは限りません。

JSONの値

JSONの申請IDと状態を読めても、その要求が取得か作成かはHTTPの方法とURLで決まります。名前より、一貫したエーピーアイ設計が重要です。ジェイソンは、データ交換でよく使われる形式です。オブジェクトは、キーと値の組で表します。配列は、複数の値を順番に持ちます。

入力とエラーの仕様

文字列、数値、真偽値、nullなどを扱えます。エーピーアイ仕様では、入力と出力の形を明確にします。エラー時の応答も、エーピーアイ仕様の一部です。

見つからないIDと権限のないIDは扱いが違います。HTTPの方法、URL、状態コード、応答の形を合わせて確認します。JSONの形だけで操作の意味は決まりません。応答の形と状態コードを合わせて読むと、成功と失敗を区別できます。
