パスワード・MFA・フィッシング耐性

パスワードを単独で強化する発想から離れ、Password manager、MFA、フィッシング耐性、回復手段まで含む認証設計を学びます。

パスワードだけを強くして終わらない

パスワードでは、使い回しを避け、一意で十分な強さを持つ秘密を管理することが重要です。複雑な記号ルールだけを増やすより、Password managerを使ってサービスごとに異なる秘密を管理する方が現実的な場合があります。

既知の漏えいパスワードを避けることも重要です。

MFAは方式の違いを見る

MFAは知識、所持、生体など異なる要素を組み合わせます。同じ種類の秘密を二回入力するだけではMFAとは言えません。

SMS、ワンタイムパスワード、Push通知などは利便性がありますが、フィッシングやMFA疲労などへの耐性が同じではありません。

フィッシング耐性を設計する

FIDOやWebAuthnなど公開鍵を用いる方式は、認証先との結び付きを利用し、偽サイトへ認証秘密を渡す危険を減らせます。Passkeyもこの系統の仕組みを利用します。

ただし端末共有、同期、回復、利用者の環境などを含めて全体のリスクを評価します。

回復経路も認証システムの一部

強い認証を導入しても、サポート窓口やアカウント回復が弱ければ、攻撃者はそこを狙います。認証器紛失時の回復手順、本人確認、監査記録をあらかじめ設計します。

新しい認証器の登録や削除、回復操作は重要なSecurity eventとして監視します。

安全性と利用可能性を両立する

高い安全性が必要な管理者や重要システムを優先しながら、段階的に強い方式へ移行する考え方もあります。利用不能、アクセシビリティ、サポート負荷も無視できません。

認証は入口の防御であり、認証後のセッション管理と合わせて初めて継続的な保護になります。
