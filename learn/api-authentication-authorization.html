認証と認可

申請APIの例で、認証と認可の違い、対象ごとの権限確認、トークンとOAuthの役割を学びます。

ログインできても、他人の申請は読めない

申請を扱うAPIで利用者Aがログインしたとします。Aが本人だと確かめる処理が認証です。Aが自分の申請を読んでよいか決める処理が認可です。ログインに成功しても、別の利用者Bの申請を読めるとは限りません。

申請IDを変えてAPIへ直接要求されることも考え、画面のボタンを隠すだけで済ませず、API側で対象申請ごとに権限を確認します。担当職員なら担当案件だけを更新できる、といった対象との関係も判断材料です。

認証状態とアクセストークン

本人確認にはパスワードや多要素認証などを使えます。認証後はセッションなどで状態を維持できます。別の構成では、保護された資源へのアクセスにアクセストークンを用います。

APIがトークンを受け取ったら、有効性、想定した用途、許された範囲を確かめます。トークンを持っているというだけで任意の申請を返す設計にはできません。誰が、どの対象へ、何をできるかを個別に判断します。

OAuthとAPIキーの違い

OAuthは、あるアプリに別サービスへの限定したアクセスを委任する枠組みです。例えば予定表アプリに予定の読み取りだけを許す場面です。OAuthのアクセストークンを得たことだけで、利用者が誰であるかの認証まで済んだとは扱いません。

APIキーは呼び出し元の識別などに使われますが、キーがあるだけで最終利用者を認証したことにはなりません。秘密情報をソースコードへ埋め込まず、漏えい時の失効も考えます。必要な操作だけを許す最小権限を守り、権限が足りなければ情報を返さずに拒否します。

この教材の扱う範囲

この章は認証と認可の役割の説明です。実装時は利用する規格の現行仕様と対象システムの権限設計を確認します。
