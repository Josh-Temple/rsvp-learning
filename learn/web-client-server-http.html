クライアント・サーバーとHTTP

この章では、ブラウザなどのクライアントとサーバーがエイチティーティーピーで通信する基本構造を学びます。

具体例で確かめる

ブラウザで申請一覧を開くと、クライアントがサーバーへHTTP要求を送ります。サーバーは認証と権限を確認してからデータを返します。

要求と応答

Webシステムでは、クライアントとサーバーが通信します。ブラウザは、代表的なクライアントです。サーバーは、要求を受けて処理し、応答を返します。エイチティーティーピーは、Webで広く使われる通信の仕組みです。

URLと操作の種類

クライアントは、エイチティーティーピー Requestを送ります。サーバーは、エイチティーティーピー Responseを返します。ユーアールエルは、アクセスする資源の場所を示します。

結果と追加情報

ブラウザがURLを開くと、サーバーへの要求と返された応答が画面表示につながります。GETは、情報取得に使われることが多いです。POSTは、新しい処理や登録に使われることが多いです。PUTやPATCHは、更新に使われることがあります。DELETEは、削除を表すために使われます。

画面に届くまで

Status Codeは、処理結果の種類を示します。Headerは、通信に関する追加情報を持ちます。Bodyは、送受信するデータ本体を持つことがあります。

画面に表示される情報は、送られた応答をブラウザが処理した結果です。通信に失敗した場合と、サーバーがエラーを返した場合を分けます。URLを知っているだけで他人のデータを見られない設計にします。通信失敗と権限による拒否は原因が違うため、どの段階で止まったか分けて調べます。

別の条件で確かめる

応答が成功でも、他人の申請が含まれたとします。通信と表示が動くことは、権限の正しさと別です。サーバーで対象ごとの閲覧権限を確認します。

画面で隠せば情報を守れるでしょうか。返すデータ自体を制限します。

通信・状態・権限を分けて考える

HTTPではクライアントが要求を送り、サーバーが応答を返します。ログイン状態のような継続的な状態は、Cookieやセッションなど別の仕組みと組み合わせて扱います。

HTTPSは通信経路の盗聴や改ざんへの対策になりますが、誰がどのデータを見てよいかという認可まで自動的に保証しません。状態コード、応答本文、認証・認可をそれぞれ確認し、通信が成功したことと業務的に正しいことを分けます。
