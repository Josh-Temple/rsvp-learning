Pull Request・Review・Issue

この章では、ギットハブで変更を提案し、レビューし、課題を追跡する基本を学びます。

基本の考え方

まず、Pull Requestは、変更を統合するための提案です。変更内容を、差分として確認できます。目的や背景を説明する文章も重要です。Reviewでは、コードや設計の問題を確認します。

関係する用語と要素

次に、動作だけでなく、保守性や安全性も見ます。コメントは、具体的な変更箇所へ付けられます。承認条件を、チームで決めることがあります。

違いと判断の視点

ここで、Issueは、課題や要望を記録するために使えます。一つのIssueからPull Requestへつなげる運用もあります。何を完了条件とするか明確にします。大きな変更は、小さなPull Requestへ分けると確認しやすくなります。

利用時に意識する点

最後に、自動テストの結果も、Review材料になります。Review履歴は、意思決定の記録にもなります。ギットハブは、コードだけでなく変更管理の場として使えます。
