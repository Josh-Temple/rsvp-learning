ネットワークと端末の防御

ネットワーク分離、通信制御、端末防御、名前解決、監視、侵入後の封じ込めを多層で組み合わせる考え方を学びます。

境界防御だけに頼らない

インターネットとの境界にファイアウォールなどを置いても、内部へ入られた後の移動や、内部利用者による誤操作までは防げません。ネットワークを分け、重要資源へ到達できる経路を絞り、必要な通信だけを許します。

分離の目的は、攻撃を完全に防ぐことだけではなく、一台の端末や一つのアカウントが侵害されたときに被害が横へ広がる範囲を小さくすることです。

入口だけでなく出口も見る

外部から入ってくる通信だけでなく、内部端末から外部へ向かう通信も確認します。不審な接続先や通常と異なる大量通信は、侵害や情報持ち出しを調べる手掛かりになります。

不要なポートやサービスを公開しないことに加え、業務上必要な通信を把握しておくと、異常な通信との違いを見つけやすくなります。

端末を継続して管理する

端末ではOSやアプリケーションを更新し、不要なソフトウェアや機能、過剰な管理者権限を減らします。端末の設定や保護機能が有効かを継続して把握することも重要です。

マルウェア対策や端末監視は有効な層の一つですが、それだけですべての攻撃を防げるわけではありません。検知を回避する攻撃や、正規の認証情報を悪用する攻撃も考えます。

暗号化通信とDNSも監視する

通信が暗号化されていても、その通信先や通信内容が安全とは限りません。暗号化は盗み見を防ぐ役割を持ちますが、マルウェアが暗号化通信を使う場合もあります。

DNSは名前を接続先へ変換する重要な基盤です。不審な名前解決、想定外の接続先、設定変更なども異常を調べる手掛かりになります。

持出し・無線・管理経路を含める

ノートPCやスマートフォンなど持ち出す端末では、紛失時の保存データ保護、利用停止、アカウント失効などを準備します。無線LANも同様に、誰がどのネットワークへ接続できるかを管理します。

重要資源へ接続する管理用経路は、通常利用の経路と分けることがあります。来訪者用と業務用を分けるなど、用途と影響に応じて境界を設けます。

侵入を前提に封じ込める

ゼロトラストの考え方では、ネットワーク内にいること自体を信頼の根拠にしません。利用者、端末、対象資源など必要な条件を確認し、必要な範囲だけアクセスを許します。

問題が起きたときに端末や通信を隔離できるようにし、その間の業務継続も考えます。多層防御は製品を増やすことではなく、一つの失敗を別の層で補う設計です。

この教材の扱う範囲

この章は防御設計の基礎です。具体的なネットワーク構成、端末製品、検知ルール、通信許可は環境ごとの脅威と要件に合わせて設計します。
