Webhookと非同期処理

この章では、イベント通知、Webhook、Queueなどを使う非同期処理の基本を学びます。

基本の考え方

まず、同期処理では、処理結果を待ってから次へ進みます。非同期処理では、結果を待たずに別の処理へ進めます。時間のかかる処理では、非同期が有効な場合があります。Webhookは、出来事が起きた側から通知する仕組みです。

関係する用語と要素

次に、例えば、決済完了後に通知を送ることができます。通知を受けるユーアールエルを、事前に登録します。Webhookは、同じ通知が複数回来る可能性も考えます。

違いと判断の視点

ここで、そのため、受信側には冪等性が重要です。Queueは、処理要求を一時的にためる仕組みです。送信側と処理側を、時間的に分離できます。再試行や失敗処理を設計しやすくなります。

利用時に意識する点

最後に、一方で、処理状況が見えにくくなることがあります。監視とログが、より重要になります。非同期化は、複雑性と引き換えに柔軟性を得る設計です。

具体例で確かめる

審査完了時に外部システムへWebhookを送るとします。受信側が一時的に停止していれば、後で再送する必要があります。再送で同じ通知が二度届いても、受付番号とイベントIDで重複を判定します。順番が入れ替わる場合は時刻だけでなく状態の遷移を確認します。送信成功と相手の処理完了を同一視しません。
