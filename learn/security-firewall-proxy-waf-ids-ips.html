Firewall・Proxy・WAF・IDS/IPS

NetworkとApplicationの防御装置を役割別に整理し、許可制御、仲介、検知、遮断を混同せず、多層防御へ配置します。

装置名ではなくSecurity functionを見る

Firewallは主に通信許可を制御し、Proxyは通信を仲介し、WAFはWeb trafficの内容を見てApplicationを補完します。IDSは異常の検知、IPSは検知に加えて遮断を行う構成があります。

名称だけでなく、実際に何を観測し、何を許可・拒否できるかを確認します。

WAFは脆弱性修正の代わりではない

WAFは既知パターンを遮断したり、一時的な緩和策になったりしますが、Applicationの設計やCodeの弱点を消すものではありません。根本修正と並行して使います。

暗号化された通信を見るにはTLS終端など配置の影響も受けます。

Rule lifecycleを管理する

緊急対応で追加した許可Ruleが永久に残ると、Attack surfaceが広がります。Ruleごとに所有者、理由、期限を持ち、不要なAny許可や古い例外を削除します。

Change管理とLogを組み合わせ、Rule変更自体も監査対象にします。

BypassとFail状態を見る

防御装置を経由しない直接接続、別Port、Cloud経路が存在すればCoverageに穴ができます。また障害時に通信を許可するFail openか、遮断するFail closedかで可用性とSecurityのTrade-offが変わります。

装置自体の管理面、Firmware、設定Backupも保護対象です。
