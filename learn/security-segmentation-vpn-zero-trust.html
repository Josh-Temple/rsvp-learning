セグメンテーション・VPN・Zero Trust

Network分割、VPN、Zero Trustを『内部なら安全』の代替として整理し、Identity・Device・Resourceを単位とする継続的なAccess判断を学びます。

分割でBlast radiusを抑える

Network segmentationは、侵入が一か所で起きても他の端末やServiceへ自由に到達できないようにする考え方です。業務、管理、開発・本番などの必要性に応じて区切り、Firewall Ruleと組み合わせます。

CloudではNetworkだけでなくAccountやProjectの分離も影響範囲を抑える手段になります。

VPN接続を信頼完了にしない

VPNはRemote accessやSite間通信を暗号化するTunnelとして有用ですが、盗まれたCredentialや侵害済みClientがVPNへ接続する可能性があります。

MFA、端末状態、接続先の最小化、Logを組み合わせます。

Zero TrustはResource中心

NIST SP 800-207では、Network位置をSecurity postureの主要要素とせず、Resourceの保護を中心にZero Trust Architectureを整理しています。Identity、Device、Access対象、Contextなどから明示的にAccessを判断します。

内部Networkにいるという理由だけで広い信頼を与えません。

段階的に実装する

Zero Trustは特定製品を導入すれば完成するものではありません。重要ResourceとAccess pathを特定し、Policy decisionとEnforcement、Log、例外を整備します。

Legacy systemや可用性、Identity障害時の緊急Accessを考慮し、既存VPNやSegmentationと組み合わせながら段階的に改善します。

短い振り返り

ネットワーク分割は、一か所で侵入が起きても別の端末やサービスへ自由に到達できないようにする対策です。業務や管理の必要に応じて範囲を区切り、クラウドではアカウントやプロジェクトの分離も検討します。

VPNは通信を暗号化する経路として役立ちますが、接続した利用者や端末の安全性を自動的に保証しません。資格情報の盗難や侵害済み端末に備え、追加認証、端末状態、許可先の限定、ログを確認します。通信の一部がVPNを通らないスプリットトンネリングの設定も、目的とリスクに照らして評価します。

Zero Trustではネットワーク内にいることだけを理由に信頼せず、対象資源と利用者、端末、状況に応じてアクセスを判断します。特定製品で一度に完成するものではなく、可用性や緊急時の経路も考慮し、既存の分割・VPNと組み合わせて段階的に整備します。

この教材の扱う範囲

Zero Trustは特定製品名ではありません。既存環境を一度に置換するのではなく、重要ResourceとAccess pathから段階的に適用します。
