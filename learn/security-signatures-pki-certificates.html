デジタル署名・PKI・証明書

デジタル署名、公開鍵証明書、CA、Trust chainを結び、TLSなどで相手を信頼する仕組みと検証の失敗条件を学びます。

署名は暗号化ではない

デジタル署名はDataを秘密にすることが主目的ではありません。署名者の秘密鍵で署名し、対応する公開鍵で検証することで、Dataの改ざん検知や署名主体との結び付きを確認します。

機密性が必要なら別に暗号化を組み合わせます。

公開鍵と主体を結び付ける

公開鍵だけを受け取っても、それが本当に目的の組織やServerの鍵か分かりません。PKIではCAが公開鍵と主体情報を結び付けた証明書を発行し、Trust chainを通じて信頼を構築します。

Root CAの信頼、Intermediate CA、証明書の署名、有効期限、名前、用途などを検証します。

失効と鍵侵害を考える

秘密鍵が漏えいした場合、証明書が期限内でも安全ではありません。侵害した鍵の利用を止め、新しい鍵と証明書へ切り替え、依存するSystemも更新します。

証明書Lifecycleは発行だけでなく、更新、失効、廃棄まで含みます。

TLSでは相手確認も重要

TLSは通信を暗号化するだけでなく、証明書を使って接続先Serverを認証する役割も持ちます。証明書警告を無視したり検証を無効化したりすると、相手確認の仕組みを壊します。

必要に応じてClient証明書を使う構成もあります。

署名済みだから安全とは限らない

Code signingはSoftwareの出所と改ざん検知に役立ちますが、署名者の環境が侵害されれば悪意あるSoftwareへ正規署名が付く可能性もあります。

鍵保護、発行権限、証明書台帳、期限監視を含めてPKIを信頼Lifecycleとして運用します。
