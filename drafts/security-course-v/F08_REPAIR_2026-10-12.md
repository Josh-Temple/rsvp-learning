## Root cause and actual code change

The prior rule was `now < grant.expires_at`. Per Python 3.12 datetime order
comparison, two aware datetimes sharing the same `tzinfo` compare wall times and
ignore `fold`. The accepted input contract also permits `ZoneInfo` datetimes.
Therefore the autumn repeated hour can invert an authorization decision.

The new rule, *after the existing aware_datetime checks*, is:

```python
now.astimezone(timezone.utc) < grant.expires_at.astimezone(timezone.utc)
```

`astimezone` preserves the same instant. **It does not use
`replace(tzinfo=timezone.utc)`**. All preexisting support-enabled, active vendor,
approved grant, valid IDs, matching actor/target, supported diagnostic-field,
attribute-availability and application-shape conditions remain unchanged.

Primary documentation (Python 3.12):
- https://docs.python.org/3.12/library/datetime.html#datetime-objects
- https://docs.python.org/3.12/library/zoneinfo.html#using-zoneinfo
