# Learn HTML 生成仕様

Status: CURRENT
Updated: 2026-09-27

## 目的

RSVP教材と同じリポジトリから、Android Chromeで連続して耳から学べるLearn版HTMLを一貫して生成するための実装仕様です。

上位ルールは Project Source の「Listen / Learn HTML 生成ルール v0.1」です。本書は、そのLearnルールをこのリポジトリの実装へ具体化したものです。内容が衝突する場合は、ユーザーの今回の個別指示、Project Source、本書の順で優先します。

## 現行方式

Learnページは、原則として単一HTMLファイルで完結させます。

読み上げはChrome標準の「このページを読み上げ」を必須経路にせず、ページ内の Web Speech API を使います。

使用API:

- `window.speechSynthesis`
- `SpeechSynthesisUtterance`

理由は `docs/LEARN_READALOUD_PILOT_20260927.md` を参照してください。

Android実機では、ページ内読み上げはChromeが前面にある状態で動作しました。Chromeを前面から外すと停止するため、バックグラウンド再生は現行仕様では保証しません。

## 入力

Learn HTMLを作るときは、次のいずれかを入力とします。

1. レビュー済みの教材原稿
2. 既存のRSVP教材の元原稿
3. 根拠資料から新たに作る教材原稿

RSVP JSONの短いチャンク列を、そのまま連結して読み上げ本文にしません。Learn本文は耳だけで理解できる連続文章として再構成します。

根拠資料がある場合、元資料にない事実を補完しません。不明な点は不明のまま扱います。

## Learn本文の構成

最初に全体像を短く示します。

基本の流れは、内容に応じて次を優先します。

1. 概念・定義
2. 具体例
3. 似た概念との違い・関係
4. 実際の場面での使われ方
5. 短い再整理

固定テンプレートとして機械的に当てはめる必要はありません。

一度に多数の新概念を投入せず、ひとつの意味のまとまりを理解してから次へ進みます。

抽象概念には、必要に応じて具体例を付けます。境界が重要なら「似ているが違う例」も使います。

重要概念は、同じ文章の単純反復ではなく、別の例・比較・応用場面から自然に再登場させます。

## 音声向け文章ルール

- 自然な日本語の書き言葉を使う
- 英語直訳調を避ける
- 一文を過度に長くしない
- 主語、対象、因果関係を音声だけでも追えるようにする
- 表、複雑な箇条書き、脚注記号、注釈番号へ依存しない
- 「上記」「下表」「右図」など画面位置を前提にしない
- ポッドキャスト風の挨拶、相槌、架空の会話を足さない
- 意図的な沈黙、回答待ち、手動操作を要求しない
- 問いかけを使う場合は、そのまま答えまで続ける
- 数字、単位、日付は耳で意味を取りやすい文脈に置く
- 不要な桁数や精度は残さない

## 略語と専門用語

専門用語は初出時に必要最小限の説明を付けます。

英字略語は、そのままTTSへ渡したときに不自然にならないようにします。必要なら、最初だけ読み方を併記します。

例:

- `オーオース、英字では OAuth`
- `エーピーアイキー、英字では API Key`

読み方を決められない固有名詞や略語を推測で補いません。

## HTML必須構造

- UTF-8
- `<html lang="ja">`
- viewport指定
- タイトルと短いdescription
- 本文は `<main>` と `<article>` を中心にする
- 見出しは `h1`〜`h3`
- 本文は `p`
- 読み上げ対象本文は初期HTML内の通常テキストとして保持
- JavaScript実行後に初めて本文が生成される構造にしない
- 外部フレームワーク、外部フォントを必須にしない
- CSSは最小限
- ナビゲーションや補助UIを増やしすぎない

現行パイロットの構造は `learn/api-authentication-authorization.html` を参照します。

## 読み上げ対象

現在の実装では、Learn本文内の次の要素をDOM順に読み上げます。

```js
article.querySelectorAll("h1, h2, p")
```

したがって、読み上げさせたくない補助表示は `article` の外へ置くか、将来セレクタを変更します。

本文を一つの巨大なutteranceにせず、見出し・段落単位で `SpeechSynthesisUtterance` を作ります。

これにより、

- 連続再生
- 現在位置の把握
- 段落ハイライト
- エラー時の切り分け

を行いやすくします。

## プレイヤー仕様

現行Learn HTMLは次を提供します。

- 再生
- 一時停止
- 停止
- 読み上げ中の段落ハイライト
- 利用可能な日本語音声の選択
- 再生速度 0.7〜4.0倍

再生速度は `SpeechSynthesisUtterance.rate` に設定します。

速度変更は、現在読み上げ中のutteranceではなく、原則として次の発話から反映されます。

音声選択を変更した場合、現行実装では現在位置から読み直します。

## 状態と操作

最低限、次の状態を扱います。

- `idle`
- `playing`
- `paused`

停止時は `speechSynthesis.cancel()` を呼び、先頭へ戻します。

ページ離脱時にも発話をキャンセルします。

`canceled` と `interrupted` は通常操作でも発生し得るため、致命的エラーとして扱いません。

## 読み上げ中の表示

現在読んでいる見出しまたは段落へクラスを付与し、視覚的にハイライトします。

ハイライトは補助機能です。内容理解に必須な情報を色だけで表現しません。

自動スクロールは現在位置を中央付近へ移動する程度にし、本文自体の構造を変えません。

## 出典

調査教材など出典が必要な場合は、本文の後に「出典」セクションを置きます。

- 本文中に生URLを置かない
- リンク文字列には資料名・媒体名を使う
- 元資料にない出典を推測で追加しない
- 事実、解釈、推測、不確実性を混同しない

出典部分が読み上げノイズになる場合は、読み上げ対象の `article` と視覚表示上の出典領域を分けてもよいです。ただし、出典を隠したり削除したりしません。

## UI

Learnは文章が主役です。

- 広い余白
- 強い見出し階層
- 操作UIは小さく
- カードを大量に並べない
- 読み上げ操作を本文より目立たせすぎない

既存サイトのBaukasten系の見た目と整合させます。

## ファイル配置

現時点では、Learn HTMLは `learn/` 以下に置きます。

例:

```text
learn/
  api-authentication-authorization.html
```

教材数が増えた場合は、RSVP教材の分野構造に合わせたサブディレクトリ化を検討します。

## 生成時チェックリスト

生成後に最低限確認します。

- `lang="ja"` がある
- 本文が初期HTMLに存在する
- `main > article` を中心に構成されている
- 本文が音声だけで理解できる
- 画面位置依存の表現がない
- 強制ポーズや回答待ちがない
- 読み方が曖昧な英字列を放置していない
- 生URLを本文へ出していない
- Web Speech APIの再生ボタンがある
- 停止、一時停止、音声選択がある
- 速度が0.7〜4.0倍
- 段落単位で読み上げる
- 読み上げ中の要素をハイライトする
- Android Chrome前面利用を前提としている
- バックグラウンド再生を保証する表現がない

## 現時点でしないこと

- Chrome標準「このページを読み上げ」が必ず表示される前提にしない
- 音声ファイルを教材ごとに生成しない
- TTS APIを必須にしない
- バックグラウンド再生のためだけに構成を複雑化しない
- Learn本文をRSVPチャンクから機械的に復元しない
