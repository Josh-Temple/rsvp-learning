## 1. 既存教材の再分割（高）

### 確認した事実

mainの79教材・1,220チャンクを集計した。

- 文字数中央値: 21
- 90%点: 28
- 最長: 44
- 24文字超: 325チャンク
- 24文字超を含む教材: 74教材

`prompts/lesson-generation.md` は4〜14文字程度を中心とする短い意味単位を求めている。固有名詞等の例外だけでなく、一文全体が一つのチャンクになっている。

例: `lessons/generative-ai/genai-rag.json` の「RAGは、モデルへ知識を完全に覚えさせる方法ではありません」は、base_duration_ms=680、duration_multiplier=1.1。8倍では約94ミリ秒となる。

一方、PR #6の情報セキュリティ16章は最長23文字で、24文字超はない。

### 影響と対応方針

同じ速度設定でも教材ごとの表示情報量が大きく違う。文字数だけで機械的に切らず、既存の生成規則と情報セキュリティ教材を参考に意味を保って分割する。

内容の修正と表示単位の変更を混同しない。条件・例外・専門用語を削らず、元原稿との対応を確認する。長い専門語は例外として個別に判断する。

### 完了条件

- [ ] 対象教材と元原稿を現在のmainから確定する。
- [ ] 分割前後で説明、条件、例外が保持されている。
- [ ] 助詞だけ、記号だけなど意味の取りにくい分割を抜き取り確認する。
- [ ] 長いチャンクの残存箇所と残す理由を確認する。
- [ ] Androidの利用画面で、通常速度と8倍前後の表示を確認する。

根拠: [生成規則](https://github.com/Josh-Temple/rsvp-learning/blob/bc82aadb772f1d024cd0bb35e26ef31ac49a85bb/prompts/lesson-generation.md)、[RAG教材](https://github.com/Josh-Temple/rsvp-learning/blob/bc82aadb772f1d024cd0bb35e26ef31ac49a85bb/lessons/generative-ai/genai-rag.json)

## 2. 章取得の競合（高）

### 確認した事実・再現条件

`startCourse()` は取得前にcourseId、mode、sequenceを変更し、`loadChapterAt()` は取得後に、その要求が現在も有効か確認せずlesson等を更新する。

再現テスト:

1. Course Aの読み込みを開始し、応答を保留する。
2. Course Bの読み込みを開始する。
3. Bの応答を先に完了させる。
4. Aの応答を後から完了させる。

実測結果: `courseId=B, sequence=[b], lessonId=a, title=a`。

### 影響と対応方針

コース、章順、表示本文が食い違う。取得要求ごとの番号などで古い結果を破棄し、選択状態と教材を整合した単位で確定する。必要に応じてAbortControllerも用いる。

### 完了条件

- [ ] A→Bと素早く選択し、応答が逆順でもBが表示される。
- [ ] 古い要求の成功・失敗で、現在の教材・エラー表示・再生状態を上書きしない。
- [ ] コース移動、前後章移動、ALL/RNDの自動送りでも本文と章順が一致する。
- [ ] 現在の要求が失敗した場合、選択状態と残っている教材が不整合にならない。
- [ ] 競合の再現条件を回帰テストとして残す。

根拠: [app.js loadChapterAt / startCourse](https://github.com/Josh-Temple/rsvp-learning/blob/bc82aadb772f1d024cd0bb35e26ef31ac49a85bb/app.js#L245-L290)

## 3. 一覧表示中の再生継続（中）

### 確認した事実

`openLibrary()` はオーバーレイを表示するだけで再生を止めない。テストでも一覧表示後に`playing=true`が維持された。

### 影響と対応方針

本文が見えない間に再生が進む。最終チャンクまで進めば完走として記録され、ALL/RNDでは次章へ進む。一覧を開く際に一時停止し、閉じただけでは自動再開しない操作を基本とする。

### 完了条件

- [ ] 再生中に一覧を開くとタイマーが停止する。
- [ ] 一覧表示中にチャンク、完走回数、次章が進まない。
- [ ] 閉じた後、明示的な再生操作で再開できる。
- [ ] 章の自動送りに伴う取得中に一覧を開いても、取得完了後に勝手に再生しない。
- [ ] 一覧表示時の停止と、上記取得中のケースを回帰テストで確認する。

根拠: [app.js openLibrary](https://github.com/Josh-Temple/rsvp-learning/blob/bc82aadb772f1d024cd0bb35e26ef31ac49a85bb/app.js#L457-L462)

## 5. 教材・カタログの自動検査（中）

### 確認した事実

JSON Schemaは存在するが、実行時の`validateLesson()`は主にtitle、chunks、chunk.textの存在・型を確認する。上記mainのツリーには、テスト、検証スクリプト、GitHub Actions workflowがない。

今回の教材・参照検査で問題が見つからなかったことと、将来の変更で仕様を守れることは別である。

### 対応方針・完了条件

- [ ] Lesson IDとCourse IDの重複を検出する。
- [ ] カタログのpath、実ファイルのid、Courseのchapter参照を照合する。
- [ ] 空白だけのチャンク、不正な表示時間、本文への不要なURL・Markdown混入を検査する。

- [ ] 出典なし・未確認の状態を検知できるが、機械検査を事実確認の代わりにしない。
- [ ] ローカルとCIで同じ検査を実行する。
