# ネットワークと端末の防御

Status: COMPLETE v0.1
Created: 2026-09-28
Updated: 2026-09-29

## 学習目標

境界防御だけに依存せず、ネットワーク分離、通信制御、端末管理、名前解決、監視、侵入後の封じ込めを組み合わせて説明できるようにします。

## 本文

1. 外部との境界だけでは守れません。
2. 内部からの攻撃も考えます。
3. 侵入後の移動も考えます。
4. ネットワークを分ける方法があります。
5. 重要資源への経路を絞ります。
6. 必要な通信だけを許します。
7. 不要なポートを公開しません。
8. 送信側の通信も管理します。
9. 分離は被害の広がりを抑えます。
10. ただし分離だけでは十分でありません。
11. 利用者と端末も確認します。
12. 接続場所だけで信用しません。
13. 端末の更新を続けます。
14. 古いソフトを放置しません。
15. 不要な機能を減らします。
16. 管理者権限を常用しません。
17. 端末の状態を把握します。
18. マルウェア対策も一層です。
19. 単一製品だけに依存しません。
20. 検知できない攻撃も考えます。
21. ログを残して異常を見ます。
22. 通信量の変化も手掛かりです。
23. 不審な接続先も調べます。
24. 平常時を知らないと比較しにくいです。
25. 暗号化通信でも安全とは限りません。
26. 中身が悪意ある場合があります。
27. DNSも重要な基盤です。
28. 名前解決の異常も調べます。
29. 持出し端末も管理対象です。
30. 紛失時の対策を用意します。
31. 保存データも保護します。
32. 遠隔停止も選択肢です。
33. 無線LANも管理対象です。
34. 来訪者用と業務用を分ける場合があります。
35. 重要資源はさらに分離します。
36. 管理経路も保護します。
37. 侵入を前提に被害を抑えます。
38. 一台の侵害を全体へ広げません。
39. 封じ込め手段を用意します。
40. 隔離後の業務継続も考えます。
41. 境界内なら信頼できますか。
42. 場所だけでは判断できません。
43. 暗号化済みなら安全ですか。
44. 送信先と挙動も確認します。
45. 多層の防御で補い合います。
46. 監視と更新を続けます。
47. 構成変更なら再評価します。
48. 通信と端末を一緒に見ます。

## 注意

この章は防御設計の基礎です。具体的なネットワーク構成、端末製品、検知ルール、通信許可は環境ごとの脅威と要件に合わせて設計します。
