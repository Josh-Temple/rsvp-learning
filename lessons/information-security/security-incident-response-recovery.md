# インシデント対応と復旧

Status: COMPLETE v0.1
Created: 2026-09-28

## 学習目標

インシデント発生後だけでなく、平時の準備、検知、影響把握、封じ込め、復旧、振り返りを一連の活動として説明できるようにします。

## 本文

1. 不審な大量通信を検知したとします。
2. まず事実を確認します。
3. 誤検知の可能性もあります。
4. 影響範囲を調べます。
5. 対象端末を特定します。
6. 対象アカウントも確認します。
7. 必要なら被害を封じ込めます。
8. 通信を止める場合があります。
9. アカウントを停止する場合もあります。
10. ただし証拠を失わないようにします。
11. ログを保存します。
12. 時刻をそろえて記録します。
13. 誰が何をしたか残します。
14. 連絡先を平時に決めます。
15. 意思決定者も決めておきます。
16. 法務や広報も関係する場合があります。
17. 外部連絡の条件を決めます。
18. 復旧は停止解除だけではありません。
19. 侵入経路を確認します。
20. 弱点を修正します。
21. 認証情報を更新する場合があります。
22. 安全な状態から再開します。
23. バックアップも検証します。
24. 復元できるか実際に試します。
25. 復旧後も監視を強めます。
26. 再侵入の兆候を確認します。
27. 原因と対応を振り返ります。
28. 検知が遅れた理由も調べます。
29. 手順を更新します。
30. 教育や設定も見直します。
31. 対応速度だけで評価しません。
32. 被害と再発を減らせたか見ます。

## 注意

この章はインシデント対応の基礎です。実際の事故では、組織の手順、契約、法令、報告義務、専門家の指示に従う必要があります。
