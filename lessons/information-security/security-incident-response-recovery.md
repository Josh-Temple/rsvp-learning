# インシデント対応と復旧

Status: COMPLETE v0.1
Created: 2026-09-28
Updated: 2026-09-29

## 学習目標

インシデント発生後だけでなく、平時の準備、検知、分析、封じ込め、復旧、証拠保全、連絡、振り返りを一連の活動として説明できるようにします。

## 本文

1. インシデント対応は平時から始まります。
2. 連絡先を事前に決めます。
3. 意思決定者も決めます。
4. 代替連絡手段も用意します。
5. 重要資産を把握しておきます。
6. 必要なログを決めておきます。
7. 時刻をそろえて記録します。
8. 演習で手順を確かめます。
9. 不審な大量通信を検知したとします。
10. まず事実を確認します。
11. 誤検知の可能性もあります。
12. 異常の基準を確認します。
13. 影響範囲を調べます。
14. 対象端末を特定します。
15. 対象アカウントも確認します。
16. 対象データも確認します。
17. 発生時刻を推定します。
18. 必要なら被害を封じ込めます。
19. 通信を止める場合があります。
20. アカウントを停止する場合もあります。
21. ただし証拠を失わないようにします。
22. ログや関連記録を保全します。
23. 誰が何をしたか残します。
24. 変更操作も記録します。
25. 法務や広報も関係する場合があります。
26. 外部連絡の条件を決めます。
27. 委託先との連絡経路も確認します。
28. 利用者への説明も検討します。
29. 復旧は再起動だけではありません。
30. 侵入経路を確認します。
31. 弱点を修正します。
32. 認証情報を更新する場合があります。
33. 安全な状態から再開します。
34. 段階的に復旧する場合もあります。
35. バックアップを検証します。
36. 復元できるか実際に試します。
37. 復旧後も監視を強めます。
38. 再侵入の兆候を確認します。
39. 原因と対応を振り返ります。
40. 検知が遅れた理由も調べます。
41. 判断が遅れた理由も調べます。
42. 手順を更新します。
43. 教育や設定も見直します。
44. 対策の有効性を再確認します。
45. 対応速度だけで評価しません。
46. 被害と再発を減らせたか見ます。
47. 演習で改善を確かめます。
48. 次の準備へ学びを戻します。

## 注意

この章はインシデント対応の基礎です。実際の事故では、組織の手順、契約、法令、報告義務、専門家の指示に従い、外部報告や証拠保全の具体要件を個別に確認します。
