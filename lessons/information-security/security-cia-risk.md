# 機密性・完全性・可用性とリスク

Status: COMPLETE v0.1
Created: 2026-09-28
Updated: 2026-09-29

## 学習目標

守る対象を情報資産として捉え、機密性・完全性・可用性、脅威・脆弱性・影響の関係から、対策の優先順位と残存リスクを説明できるようにします。

## 本文

1. 守る対象を資産として捉えます。
2. 情報だけが資産ではありません。
3. 業務やシステムも対象です。
4. 人や設備も依存関係に入ります。
5. 機密性は閲覧範囲を守ります。
6. 完全性は正しさを守ります。
7. 可用性は必要時の利用を守ります。
8. 三つは互いに代替できません。
9. 暗号化だけでは停止を防げません。
10. バックアップだけでは漏えいを防げません。
11. 脅威は損害の原因になり得ます。
12. 攻撃者だけが脅威ではありません。
13. 誤操作や故障や災害も含みます。
14. 脆弱性は利用され得る弱点です。
15. 古いソフトも弱点になります。
16. 過剰権限も弱点になります。
17. 設定ミスも弱点になります。
18. 影響は起きた損害の大きさです。
19. 同じ弱点でも影響は変わります。
20. 公開情報と個人情報では違います。
21. 重要業務の停止なら影響も大きいです。
22. 起こりやすさも判断材料です。
23. 一つの数値だけで決めません。
24. 資産と文脈を合わせて見ます。
25. 対策は目的で分けられます。
26. 予防は発生を減らします。
27. 検知は異常を早く知るためです。
28. 復旧は影響を短くします。
29. 一つの対策だけに依存しません。
30. 多層で失敗を補い合います。
31. 対策後にもリスクは残ります。
32. 残存リスクを記録します。
33. 回避する判断があります。
34. 低減する判断があります。
35. 移転する判断もあります。
36. 受容する判断もあります。
37. 受容には責任ある判断が要ります。
38. 環境変化で前提は変わります。
39. 新しい委託先も変化です。
40. 新しい機能も変化です。
41. 重大変更なら再評価します。
42. 指標で対策の効き目を見ます。
43. 対策の存在だけでは安心しません。
44. 実際の結果を確認します。
45. 顧客名簿を例に考えます。
46. 漏えい防止だけでは足りません。
47. 誤更新と停止も考えます。
48. 三つの性質を同時に見ます。
49. 守る対象から判断を始めます。

## 注意

この章はリスク管理の基礎です。組織固有の評価尺度、法令上の要求、具体的な管理策は対象組織のルールと一次資料を確認します。
