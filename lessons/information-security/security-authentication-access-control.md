# 認証・認可・アクセス制御

Status: COMPLETE v0.1
Created: 2026-09-28
Updated: 2026-09-29

## 学習目標

本人確認、認証、認可を区別し、認証要素、最小権限、権限モデル、セッション管理、付与・変更・剥奪を一連のアクセス制御として説明できるようにします。

## 本文

1. 利用者Aがログインするとします。
2. 誰かを確かめるのが認証です。
3. その前に本人確認がある場合もあります。
4. 認証と本人確認は同じではありません。
5. 何を許すか決めるのが認可です。
6. 認証と認可は別の判断です。
7. ログイン済みでも全件は読めません。
8. 対象と操作ごとに確認します。
9. 認証要素には種類があります。
10. 知っている情報があります。
11. 持っている物があります。
12. 本人の特徴も使われます。
13. 異なる要素を組み合わせます。
14. 多要素認証は認証を強めます。
15. 同じ種類を二つ使うとは限りません。
16. 強い認証でも権限は別です。
17. 最小権限で必要分だけ許します。
18. 役割で権限をまとめる方法があります。
19. 属性で条件を決める方法もあります。
20. 方式は用途に合わせて選びます。
21. 画面を隠すだけでは不十分です。
22. サーバー側でも認可します。
23. IDを変えた要求にも備えます。
24. 所有関係も確認します。
25. セッションも管理対象です。
26. 有効期限を設けます。
27. 失効できる仕組みを用意します。
28. トークンの権限範囲も確認します。
29. 共有アカウントは追跡を難しくします。
30. 利用者ごとに識別します。
31. 異動時は権限を見直します。
32. 退職時は利用を停止します。
33. 一時権限には期限を置きます。
34. 不要な権限を残しません。
35. 定期的に実効権限を確認します。
36. 役割名だけでは判断しません。
37. 端末の状態も判断材料になります。
38. 接続場所だけで信用しません。
39. 毎回必要な条件を確認します。
40. 継続的にアクセスを評価します。
41. 認証済みなら安全でしょうか。
42. 対象と操作の認可も必要です。
43. MFA済みなら管理者ですか。
44. 認証の強さと権限は別です。
45. 権限付与には承認を残します。
46. 剥奪まで含めて設計します。
47. 例外権限も記録します。
48. 誰が何をできるか追跡します。

## 注意

この章はアクセス制御の基礎です。具体的な認証方式、保証レベル、トークン形式、権限モデルは利用する規格・システム・組織ルールを確認します。
