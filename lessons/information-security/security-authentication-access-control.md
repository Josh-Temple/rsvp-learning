# 認証・認可・アクセス制御

Status: COMPLETE v0.1
Created: 2026-09-28

## 学習目標

認証と認可を区別し、認証要素、最小権限、権限の付与・変更・剥奪を一連のアクセス制御として説明できるようにします。

## 本文

1. 利用者Aがログインするとします。
2. 誰かを確かめるのが認証です。
3. 何を許すか決めるのが認可です。
4. 二つは別の判断です。
5. 認証要素には種類があります。
6. 知っている情報があります。
7. 持っている物があります。
8. 本人の特徴も使われます。
9. 異なる要素を組み合わせます。
10. 多要素認証は認証を強めます。
11. ただし権限は別に確認します。
12. 管理者権限が必要とは限りません。
13. 最小権限で必要分だけ許します。
14. 対象ごとに権限を確認します。
15. 操作ごとにも権限を確認します。
16. 画面を隠すだけでは不十分です。
17. サーバー側でも制御します。
18. 共有アカウントは追跡を難しくします。
19. 利用者ごとに識別できる形にします。
20. 異動時は権限を見直します。
21. 退職時は利用を停止します。
22. 一時権限には期限を置きます。
23. 不要な権限を残しません。
24. 定期的に実効権限を確認します。
25. 認証情報の漏えいにも備えます。
26. 失効できる仕組みを用意します。
27. 強い認証でも全件閲覧は別です。
28. 端末の状態も判断材料になります。
29. ネットワーク内でも無条件に信じません。
30. 毎回必要な条件を確認します。
31. 認証済みなら安全でしょうか。
32. 対象と操作の認可も必要です。

## 注意

この章はアクセス制御の基礎です。具体的な認証方式や保証レベル、組織の権限設計は利用する規格・システム・組織ルールを確認します。
