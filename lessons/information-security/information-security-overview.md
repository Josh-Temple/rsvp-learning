# 情報セキュリティ概観

Status: DRAFT v0.1
Created: 2026-09-27
Updated: 2026-10-22

## 学習目標

情報セキュリティを守る対象から説明し、機密性・完全性・可用性を架空の同一事例で区別します。また、脅威と脆弱性、認証と認可、予防と復旧の役割の違いを説明できるようにします。

## 本文

1. 情報セキュリティは、
2. 情報と業務を守る考え方です。
3. 守るのはデータだけではありません。
4. システムや人の業務も対象です。
5. まず何を守るか明確にします。
6. 次に三つの性質を考えます。
7. 機密性は、
8. 許可のない開示を防ぎます。
9. 完全性は、
10. 情報の正確さと完全さを守ります。
11. 可用性は、
12. 必要なときに使えることです。
13. 三つは互いに代用できません。
14. 架空の予約サイトを考えます。
15. 予約者の情報が漏れた場合は、
16. 機密性が損なわれます。
17. 予約日時が勝手に変われば、
18. 完全性が損なわれます。
19. 画面が開かず予約できなければ、
20. 可用性が損なわれます。
21. 同じサービスでも問題は異なります。
22. 脅威は損害の原因になり得ます。
23. 攻撃だけでなく故障も脅威です。
24. 脆弱性は利用され得る弱点です。
25. 設定ミスも弱点の一例です。
26. 脅威と弱点を同一視しません。
27. リスクを考えるときは、
28. 起こりやすさと影響を見ます。
29. 重要な情報かどうかも関係します。
30. 対策を入れてもリスクは残ります。
31. 次にアクセス制御を考えます。
32. 認証は本人かを確かめます。
33. 認可は操作の権限を判断します。
34. ログインできても、
35. 閲覧できる情報は権限で決まります。
36. 暗号化は鍵を使い暗号文に変えます。
37. しかし停止そのものは防げません。
38. バックアップは復旧に役立ちます。
39. しかし漏えい防止とは別です。
40. 一つの対策だけに頼りません。
41. 人の確認や運用も重要です。
42. 異常を見つける仕組みも要ります。
43. 事故が起きたら影響を確かめます。
44. 被害を広げない対応を考えます。
45. 復旧後は原因と再発防止を見ます。
46. ここで問いを一つ考えます。
47. 予約サイトが止まったとき、
48. まず損なわれるのは何でしょう。
49. 利用できないので可用性です。
50. 情報漏えいも同時に起きたかは、
51. 別の証拠がなければ分かりません。
52. この章は全体像の入口です。
53. 制度や実装の詳細は別章で学びます。

## 注意

予約サイトは理解のための架空例です。被害の発生事実や規模について述べるものではありません。この候補は独立内容レビュー前の `DRAFT v0.1` です。セキュリティ上の具体的な推奨、制度・規格の要求、実装手順を確定する教材ではありません。
