# 暗号・ハッシュ・デジタル署名

Status: COMPLETE v0.1
Created: 2026-09-28
Updated: 2026-09-29

## 学習目標

暗号化、ハッシュ、デジタル署名を目的別に区別し、共通鍵・公開鍵、パスワード保存、鍵のライフサイクルまで含めて安全性を説明できるようにします。

## 本文

1. 暗号化は内容を読みにくくします。
2. 復号には対応する鍵を使います。
3. 共通鍵方式では秘密鍵を共有します。
4. 同じ鍵の管理が重要になります。
5. 公開鍵方式は鍵の役割を分けます。
6. 公開鍵と秘密鍵を使います。
7. 用途に応じて方式を組み合わせます。
8. 一方が常に優れるわけではありません。
9. 暗号化は機密性に使われます。
10. 改ざん検知とは目的が違います。
11. ハッシュは要約値を作ります。
12. 入力が変われば値も変わります。
13. 通常は元へ戻す用途ではありません。
14. 完全性確認に利用できます。
15. パスワード保存にも使われます。
16. 単純な高速ハッシュだけでは足りません。
17. 専用の保存方式を使います。
18. ソルトも攻撃耐性を高めます。
19. デジタル署名は署名者を確かめます。
20. データ変更の検知にも使えます。
21. 署名と暗号化は目的が違います。
22. 秘密にしたいなら暗号化を考えます。
23. 変更を見たいなら完全性を考えます。
24. 署名者を見たいなら署名を考えます。
25. 通信では複数方式を組み合わせます。
26. 鍵交換と暗号化を分けて考えます。
27. 強い方式でも鍵漏えいは危険です。
28. 鍵管理まで含めて安全性を見ます。
29. 鍵の生成も管理対象です。
30. 保存場所も管理対象です。
31. 配布方法も管理対象です。
32. 利用権限も管理します。
33. 更新と失効も管理します。
34. バックアップも慎重に扱います。
35. 鍵ごとに用途を分けます。
36. 秘密鍵を共有しすぎません。
37. 暗号方式を自作しません。
38. 標準方式を適切に利用します。
39. 乱数の品質も重要です。
40. 実装ミスでも安全性は崩れます。
41. 暗号化済みなら安全でしょうか。
42. 鍵と設定まで確認します。
43. 署名済みなら内容は秘密ですか。
44. 署名は機密化を保証しません。
45. ハッシュ一致だけで送信者は分かりません。
46. 目的に合う仕組みを選びます。
47. 方式名だけで判断しません。
48. 運用まで含めて確認します。

## 注意

この章は暗号技術の概念理解用です。具体的なアルゴリズム、鍵長、パスワード保存方式、利用可否は用途と時点により変わるため、最新の標準・製品仕様を確認します。
