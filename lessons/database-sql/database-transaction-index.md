# トランザクションとインデックス

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

データ更新の整合性を守るトランザクションと、検索性能を支えるインデックスの基本を学びます。

## 本文

1. 口座AからBへ送金するとき、Aから引いた後で処理が失敗し、Bへ足されないままでは困ります。
2. 二つの更新を一つの取引として扱い、失敗時はまとめて戻します。
3. トランザクションは、複数の処理を一まとまりとして扱います
4. 途中で失敗した場合、処理を取り消すことがあります
5. これをrollbackと呼びます
6. すべて成功したら、変更を確定します
7. これをcommitと呼びます
8. ACIDは、トランザクションの代表的な性質を表します
9. Atomicityは、処理を全部成功か全部失敗にします
10. Consistencyは、整合性を保つことに関係します
11. Isolationは、同時実行の影響を制御します
12. Durabilityは、確定した結果を保持する性質です
13. 送金の二つの更新を一緒に確定すれば、途中失敗で片方だけが残る状態を避けられます。
14. インデックスは、検索を高速化するための構造です
15. ただし、インデックスにも保存容量と更新コストがあります
16. すべての列へ付ければ良いわけではありません
17. 整合性と性能は、用途に応じて設計します
18. 別の例として、注文IDで一件を頻繁に探すなら索引が役立ちます。
19. 索引は読み取りを助ける一方、書込み時の更新と保存領域を要します。
20. 取引と索引は異なる問題を解きます。
21. 索引は検索のための仕組みなので、送金の整合性を保証するトランザクションとは役割が違います。
22. 同じ口座へ二人が同時に入金します。
23. 双方が古い残高を基に上書きすると一方が消えます。
24. 同時更新をどう隔離するか決めます。
25. 索引を増やせばこの問題を防げますか。
26. 検索性能と更新の整合性は別です。
