# トランザクションとインデックス

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

トランザクションのACID、同時更新の問題、インデックスの役割とコストを区別し、整合性と検索性能を別々に判断する基礎を学びます。

## 本文

1. 口座AからBへ送金するとします。
2. Aだけ減って処理が止まると困ります。
3. 二つの更新を一まとまりにします。
4. 失敗時はまとめて戻します。
5. 成功時はまとめて確定します。
6. これがトランザクションの基本です。
7. Atomicityは全体性を守ります。
8. 途中だけ残る状態を避けます。
9. Consistencyは整合性に関係します。
10. 制約や処理規則も整合性を支えます。
11. Isolationは同時実行を扱います。
12. 互いの途中状態をどう見せるか決めます。
13. Durabilityは確定結果を保持します。
14. 確定後の結果が失われにくくなります。
15. 同じ口座へ同時入金するとします。
16. 双方が古い残高を読むと危険です。
17. 一方の更新が消えることがあります。
18. 同時更新の扱いを設計します。
19. 隔離の強さには違いがあります。
20. 強くすれば常に最良とは限りません。
21. 待ち時間や競合も増え得ます。
22. 次に検索性能を考えます。
23. インデックスは検索を助ける構造です。
24. 注文IDの検索などで役立ちます。
25. ただし更新時にも維持が必要です。
26. 保存領域も追加で使います。
27. すべての列に付ければよくありません。
28. 検索条件と利用頻度を見て決めます。
29. 索引は整合性を保証しません。
30. トランザクションとは役割が違います。
31. 索引を増やせば競合を防げますか。
32. 同時更新の問題は別に扱います。
33. 検索が遅いなら実行計画も確認します。
34. 整合性と性能を分けて診断します。

## 注意

この章は基礎理解用です。具体的なDB製品の隔離レベル、実行計画、索引方式は製品ごとに確認します。
