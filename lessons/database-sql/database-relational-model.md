# リレーショナルモデルの基本

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

テーブル、行、列、主キー、外部キーなどリレーショナルデータベースの基本構造を学びます。

## 本文

1. 顧客表に顧客IDと氏名、注文表に注文IDと顧客IDを置きます。
2. 顧客IDは顧客表の行を識別する主キーです。
3. リレーショナルデータベースは、表の関係としてデータを扱います
4. 表を、テーブルと呼びます
5. 一件分のデータを、行として表します
6. 属性を、列として表します
7. 主キーは、行を一意に識別します
8. 同じ主キーを、複数の行で使わないようにします
9. 外部キーは、別のテーブルの行との関係を表します
10. 例えば、注文は顧客IDを持つことがあります
11. 顧客情報を毎回注文表へ重複保存する必要はありません
12. 関係を使うことで、データを分けて管理できます
13. 注文表に顧客名を毎回書かずに済むのは、顧客IDで顧客表の行をたどれるからです。
14. NULLは、値が不明または未設定であることを表し、ゼロや空文字とは別に扱われます
15. データ型は、列に入る値の種類を定めます
16. 制約は、データの整合性を守るために使われます
17. 良いデータ設計は、業務上の関係を正しく表します
18. 注文表の顧客IDを、顧客表を参照する外部キーとして設定します。
19. 一人の顧客に注文が二件あれば、注文表には同じ顧客IDが二行現れます。
20. 注文IDだけで顧客名を探すには、二つの表の関係をたどります。
21. 外部キー制約を設定しても、顧客名や住所をどの時点の情報として表示するかは別に決めます。
22. 顧客を削除した後も注文を残したいとします。
23. 参照整合性と保存期間の両方を決めます。
24. 削除を禁止するか、履歴を別に保つか選びます。
25. 外部キーだけで保存方針は決まりますか。
26. 業務上の履歴の意味も必要です。
