# 正規化の基本

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

注文と顧客の例から、更新時の矛盾、第一〜第三正規形、意図的な重複の扱いを学びます。

## 本文

1. 注文表に、注文IDと顧客ID、顧客名と住所を保存するとします。
2. 同じ顧客が五回注文すると、名前と住所も五回記録されます。
3. 引っ越し後に一行だけ直すと、同じ顧客に二つの住所が残ります。
4. これは、更新時に生じる矛盾の例です。
5. 顧客IDと名前、住所は顧客表へまとめます。
6. 注文表には、注文IDと顧客ID、注文日を残します。
7. 顧客の住所は一か所で管理し、必要なときに二つの表を結びます。
8. このように、事実を適切な表へ分ける考え方が正規化です。
9. 第一正規形は、一つの欄に複数の値や繰り返し項目を詰め込まない形です。
10. 注文表の商品一、商品二という列より、注文明細を行で持ちます。
11. 注文明細のキーを、注文IDと商品IDの組とします。
12. 商品名が商品IDだけで決まるなら、組全体へ依存していません。
13. 第一正規形を満たし、こうした部分的な依存を分けるのが第二正規形です。
14. 商品名は商品表へ移し、明細には商品IDと数量を置けます。
15. 第三正規形では、非キー項目を経由する依存も整理します。
16. 注文IDから顧客IDが決まり、顧客IDから顧客名が決まる例です。
17. 顧客名は注文表で繰り返さず、顧客表に置きます。
18. ただし、注文時に確定した配送先や単価は、後日の変更と区別が必要です。
19. 現在の顧客住所を参照するのか、当時の配送先を保存するのかを業務要件で決めます。
20. 分割すれば必ず速くなるわけではなく、結合や運用の負担も増えます。
21. 性能のため意図的に重複させる場合は、どちらを正本とし、どう同期するかを決めます。
22. 正規化は、重複を一律に消すことではなく、事実の意味と更新規則を揃える手段です。
