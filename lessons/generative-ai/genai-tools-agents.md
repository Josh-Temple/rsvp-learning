# Tool CallingとAgent

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

LLMが外部ツールを使う仕組みと、複数ステップを進めるAgentの設計上の注意点を学びます。

## 本文

1. AIが申請状況を調べ、必要なら担当者へ通知するとします。
2. 検索は読み取りですが、通知は外部へ作用する操作です。
3. LLMは、文章を生成するだけでなく外部機能を呼び出せます
4. これを、Tool Callingとして扱います
5. 例えば、検索、計算、データ取得をツールへ任せられます
6. モデルは、用意されたツールの中から、呼び出すツール名と引数を応答として返します
7. 実際の処理は、呼び出し側のアプリがツール名と引数を確認して実行します
8. ツールの結果を、再びLLMへ返します
9. Agentでは、この判断と実行を複数回繰り返すことがあります
10. 複雑な仕事を、複数ステップへ分けられます
11. 一方で、実行回数が増えるほど失敗経路も増えます
12. 書込みや送信などの副作用には特に注意します
13. 通知の前に検索結果を読めても、その情報を誰へ送ってよいかは別の判断です。
14. 権限を必要最小限にします
15. 重要な操作前に、人間承認を置くことがあります
16. 途中状態と実行履歴を記録すると復旧しやすくなります
17. Agentは、自律性より制御可能性を含めて設計します
18. AIが選んだ宛先と内容を、送信前に権限と対象案件で検査します。
19. 応答が遅くても、同じ通知を無条件に再送すると重複するかもしれません。
20. 各呼出しの入力と結果を記録し、失敗後に何を再試行できるか決めます。
21. 再試行では検索と通知を同じように扱わず、重複や外部への作用を確認します。
22. 検索結果が正しくても、宛先が別部署だとします。
23. 通知という外部操作の前に止める必要があります。
24. 宛先と対象案件の権限を照合します。
25. 検索が成功すれば送信してよいですか。
26. 送信の条件を独立に検証します。

27. 読取りと書込みを分けます。
28. 外部作用には追加確認を置きます。
29. ツール引数も検証します。
30. 権限はツール側でも確認します。
31. 成功応答だけで結果を信じません。
32. 実行結果を読み戻します。
33. 連鎖実行には上限を置きます。
34. 停止条件を明確にします。

## 注意

この章は基礎理解用です。
特定クラウド事業者、特定LLM、特定フレームワークの最新仕様を説明する教材ではありません。
製品固有の仕様や現在の制約は、利用時点の公式資料で確認します。
