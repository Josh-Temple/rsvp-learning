# 6. 組織としてのセキュリティ運用

Status: Draft v0.2  
確認日: 2026-09-27

## 1. セキュリティは組織の活動である

情報セキュリティは、セキュリティ担当者だけの仕事ではありません。

経営層、システム担当者、利用者、委託先など、それぞれに役割があります。

組織として、何を守るのか、どの程度のリスクを受け入れるのか、誰が判断するのかを明確にする必要があります。

NIST Cybersecurity Framework 2.0では、Governが独立した機能として位置付けられています。

これは、セキュリティを技術だけでなく、組織のリスク管理として扱う重要性を示しています。

## 2. ログと監視

問題が起きたときに状況を確認するには、適切なログが必要です。

認証、重要な操作、設定変更、異常な通信などを記録することで、インシデントの検知や原因調査に役立ちます。

ただし、ログを保存するだけでは十分ではありません。

必要なログが記録されているか、時刻が整合しているか、改ざんから保護されているか、異常を確認する仕組みがあるかを考える必要があります。

ログには個人情報などが含まれる場合もあるため、保管やアクセス権にも注意が必要です。

## 3. バックアップ

バックアップは、障害、誤操作、ランサム攻撃などからデータやシステムを復旧するために重要です。

しかし、バックアップを作成しているだけでは復旧できるとは限りません。

必要なデータが含まれているか。

バックアップ自体が攻撃者に削除されたり、暗号化されたりしないよう保護されているか。

実際に復元できるか。

復旧に必要な時間が業務上許容できるか。

こうした点を確認する必要があります。

復元テストは、バックアップ運用の重要な一部です。

## 4. インシデント対応

セキュリティ上の問題が発生したときは、事前に決めた役割と手順に基づいて対応します。

影響範囲を把握します。

被害の拡大を抑えます。

原因や侵入経路を調査します。

必要な復旧を行います。

関係者への連絡や報告が必要になる場合もあります。

復旧後には、原因や対応を振り返り、再発防止や改善へつなげます。

実際のインシデント対応では、これらの作業が常にきれいな順番で進むとは限りません。

調査しながら封じ込めを行い、復旧しながら追加の影響が見つかることもあります。

NIST SP 800-61 Rev. 3では、インシデント対応を独立した一時的な作業ではなく、CSF 2.0の六つの機能すべてに関係するサイバーセキュリティリスク管理の一部として扱っています。

## 5. 委託先とサプライチェーン

組織の情報やシステムは、自組織だけで完結しないことがあります。

クラウド事業者、ソフトウェア提供者、保守会社、業務委託先など、多くの外部組織が関係します。

自組織の対策が十分でも、委託先や利用する製品を経由して影響を受ける可能性があります。

契約時の確認だけでなく、どの情報や権限を外部へ渡しているかを把握し、変更や事故に対応できるようにしておく必要があります。

## 6. 教育と仕組み

利用者への教育は重要です。

しかし、事故が起きるたびに利用者の注意だけを強化する方法には限界があります。

誤操作しにくい画面にする。

危険な操作には確認や制限を設ける。

多要素認証を使う。

不要な権限を与えない。

異常を検知できるようにする。

人が間違える可能性を前提に、技術と運用の両方で被害を抑えることが重要です。

## 7. 継続的改善

セキュリティ対策は、導入した数ではなく、実際のリスクをどの程度管理できているかを見る必要があります。

環境の変化、インシデント、監査、訓練などから得た情報を使って対策を見直します。

新しい対策を追加するだけでなく、不要になった仕組みを整理することも運用負担の軽減につながります。
