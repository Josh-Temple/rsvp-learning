# 4. 暗号とデータ保護

Status: Draft v0.2  
確認日: 2026-09-27

## 1. 暗号化の目的

暗号化は、情報をそのままでは読めない形へ変換し、適切な鍵を持つ者だけが元の情報を利用できるようにする技術です。

暗号化は主に機密性を守るために使われます。

ただし、暗号化しているだけで情報セキュリティ上の問題がすべて解決するわけではありません。

鍵の管理、認証、アクセス制御、バックアップなども必要です。

## 2. 共通鍵暗号

共通鍵暗号では、暗号化と復号に同じ秘密の鍵を使います。

大量のデータを効率よく暗号化しやすいことが特徴です。

AESは代表的な共通鍵暗号方式です。

AESには128ビット、192ビット、256ビットの鍵長があります。

実際の安全性は、アルゴリズム名だけでなく、利用モード、鍵管理、実装などにも左右されます。

## 3. 公開鍵暗号

公開鍵暗号では、数学的に関係する二つの鍵を使います。

一方を公開鍵として配布し、もう一方を秘密鍵として保護します。

公開鍵暗号は、暗号化だけでなく、鍵交換やデジタル署名などにも利用されます。

公開鍵と秘密鍵の役割は、利用する方式や目的によって異なります。

単純に「公開鍵で暗号化し、秘密鍵で復号する技術」とだけ覚えると、署名などの用途を理解しにくくなります。

## 4. ハッシュ関数

暗号学的ハッシュ関数は、入力データから一定の長さのハッシュ値を計算する仕組みです。

暗号化とは異なり、ハッシュ値から元のデータへ戻すことを目的としていません。

ファイルが変化したかを確認する用途などに使われます。

ただし、ハッシュ値だけでは、その値を提示した相手が正しい相手かまでは確認できません。

改ざんへの対策では、用途に応じてデジタル署名など別の仕組みと組み合わせます。

パスワードを保存するときもハッシュを利用しますが、単純な高速ハッシュをそのまま使うのは適切ではありません。

パスワード保存には、ソルトと、パスワード保存向けに設計された方式を使う必要があります。

## 5. デジタル署名

デジタル署名は、データの出所の真正性と、署名後にデータが変更されていないことを確認するために使われます。

秘密鍵で署名を生成し、対応する公開鍵で署名を検証します。

正しく運用するには、その公開鍵が誰に対応するものかを信頼できる方法で確認する仕組みも必要です。

デジタル署名は、データを読めなくするための暗号化とは目的が異なります。

デジタル署名そのものは、機密性を提供しません。

## 6. 通信の保護

Webでは、HTTPSを利用することで、ブラウザとサーバーの間の通信をTLSで保護します。

TLSでは暗号化だけでなく、通信相手の認証や改ざん検知に関係する仕組みも使われます。

ただし、HTTPSで接続しているから、そのサイトの内容そのものが安全であるとは限りません。

攻撃者が管理するサイトでもHTTPSを利用することはできます。

通信経路の保護と、相手が信頼できるかどうかの判断は別の問題です。

## 7. 鍵管理

暗号技術では、鍵の管理が非常に重要です。

強い暗号方式を使っていても、秘密鍵が漏れれば保護は失われます。

鍵の生成、保存、利用、交換、失効、廃棄までを考える必要があります。

暗号方式を自作するより、十分に検討された標準方式と信頼できる実装を利用することが基本です。
