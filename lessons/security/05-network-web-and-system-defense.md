# ネットワーク・Web・システム防御の全体像

Status: Draft v0.3  
確認日: 2026-09-27

この原稿は、防御技術を個別に詳しく説明する章ではありません。

ネットワーク、Web、端末、認証などの対策が、どのように組み合わさるかを理解するための全体像です。

詳細は `network-mail-defense.md`、`application-database-security.md`、`endpoint-cloud-physical-security.md` で扱います。

## 1. 一つの境界だけでは守れない

組織のネットワークと外部ネットワークの境界を守ることは重要です。

しかし、クラウド、モバイル端末、リモートアクセスが広がり、社内と社外だけで安全性を判断することは難しくなっています。

利用者。

端末。

通信。

アプリケーション。

データ。

複数の場所で安全性を確認する必要があります。

## 2. 通信を減らす

不要な通信を許可しなければ、攻撃可能な範囲を小さくできます。

ファイアウォールやネットワーク分割は、この考え方を実現する手段です。

ただし、許可された通信の中にも攻撃は入り得ます。

通信を許可するかどうかと、通信内容が安全かどうかは別の問題です。

## 3. 暗黙に信頼しない

社内ネットワークにいる。

会社の端末を使っている。

その理由だけで無条件に信頼することは避けます。

NISTのゼロトラストも、ネットワーク上の場所だけを理由に暗黙の信頼を与えない考え方です。

利用者、端末、権限、対象資源、状況などを確認します。

## 4. アプリケーション自身も守る

ネットワークで通信を制限しても、Webアプリケーション自体に脆弱性があれば攻撃される可能性があります。

認証。

アクセス制御。

入力処理。

セッション管理。

暗号。

ログ。

安全な開発と運用が必要です。

## 5. 端末も攻撃経路になる

利用者の端末が侵害されると、正規利用者の権限で内部システムへアクセスされる可能性があります。

そのため、端末の更新、権限管理、マルウェア対策も防御の一部になります。

EDRのような端末監視・対応の仕組みも利用されます。

ネットワークだけを守る設計では不十分です。

## 6. 更新と設定を維持する

安全な製品でも、古いバージョンや不適切な設定で使えばリスクが高まります。

利用中の機器やソフトウェアを把握します。

修正版を適切に適用します。

不要な機能を止めます。

初期設定のまま使わず、必要な設定を維持します。

## 7. 多層防御

一つの対策が失敗しても、別の対策で被害を抑える考え方があります。

認証。

アクセス制御。

ネットワーク分割。

端末防御。

アプリケーション防御。

ログ監視。

バックアップ。

それぞれが異なる役割を持ちます。

重要なのは、製品を多く導入することではありません。

想定する攻撃や障害に対して、各対策が何を防ぎ、何を防げないかを理解して組み合わせることです。
