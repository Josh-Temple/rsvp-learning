# 5. ネットワーク・Web・システムの防御

Status: Draft v0.1  
確認日: 2026-09-27

## 1. 防御は境界だけではない

以前から、組織のネットワークと外部ネットワークの境界を守る考え方は重要でした。

しかし、クラウドサービス、モバイル端末、リモートアクセスなどが広がり、単純に社内と社外だけで安全性を判断することは難しくなっています。

ネットワークの場所だけを信用せず、利用者、端末、権限、通信、データなど複数の条件を見る必要があります。

## 2. ファイアウォール

ファイアウォールは、通信の送信元、宛先、ポート、状態などの条件に基づいて、通信を許可または拒否するために使われます。

不要な通信を減らすことは、攻撃可能な範囲を小さくすることにつながります。

ただし、許可された通信の中に悪意あるデータが含まれる場合もあります。

ファイアウォールだけで、すべての攻撃を防ぐことはできません。

## 3. ネットワーク分割

重要なシステムと一般利用の端末を同じ範囲へ無制限に接続すると、一つの端末が侵害されたときに被害が広がりやすくなります。

用途や重要度に応じてネットワークを分け、必要な通信だけを許可する方法があります。

これは侵入そのものを完全に防ぐためだけではありません。

侵入後の横方向への移動や被害範囲を制限する目的もあります。

## 4. VPN

VPNは、離れた場所との通信を保護するために使われます。

リモートアクセスVPNでは、利用者の端末から組織の環境などへ暗号化された通信経路を作ることがあります。

しかし、VPNへ接続した利用者や端末が自動的に安全になるわけではありません。

VPNアカウントの認証強化、端末管理、VPN製品自体の脆弱性対応も必要です。

## 5. Webアプリケーション

Webアプリケーションでは、認証、アクセス制御、入力処理、セッション管理、暗号、ログなど、多くの部分がセキュリティに関係します。

OWASP Top 10は、Webアプリケーションで重要なセキュリティリスクを整理した啓発資料です。

2025年版では、アクセス制御の不備、セキュリティ設定の不備、ソフトウェアサプライチェーンの不備などが含まれています。

OWASP Top 10は、すべての脆弱性を列挙した一覧ではありません。

開発やレビューで注意すべき主要なリスクを理解するために利用します。

## 6. 更新と設定管理

安全なシステムを維持するには、ソフトウェアを適切に更新する必要があります。

同時に、不要なサービスを停止し、初期設定のまま使わず、適切な設定を維持することも重要です。

ソフトウェアのバージョン、利用中の機器、クラウドサービスなどを把握していなければ、脆弱性が公表されても自分の環境への影響を判断できません。

資産管理は、セキュリティ対策の基礎になります。

## 7. 多層防御

一つの防御機能が失敗しても、別の防御によって被害を抑える考え方があります。

認証、アクセス制御、ネットワーク分割、端末防御、ログ監視、バックアップなどを重ねて使います。

重要なのは、製品を数多く導入することではありません。

想定する攻撃や障害に対して、それぞれの対策がどの役割を持つかを理解して組み合わせることです。
