# 3. 主な攻撃手法と脆弱性

Status: Draft v0.1  
確認日: 2026-09-27

## 1. 攻撃は一つの方法だけで起きるとは限らない

サイバー攻撃は、単一の技術だけで完結するとは限りません。

人をだまして認証情報を盗み、その情報でログインし、権限を広げ、データを盗むというように、複数の手法が組み合わされることがあります。

そのため、個別の攻撃名だけでなく、攻撃者がどこから侵入し、何を狙うのかを考えることが重要です。

## 2. フィッシング

フィッシングは、正規の組織や人物を装ったメッセージなどを使い、利用者を偽サイトへ誘導したり、認証情報などを入力させたりする手口です。

メールだけでなく、SMSやSNSなどが使われることもあります。

見た目だけで完全に見分けることは難しい場合があります。

不自然な要求、緊急性を強く訴える内容、リンク先などを確認し、疑わしい場合はメッセージ内のリンクとは別の方法で正規サイトへアクセスします。

多要素認証も被害を減らす手段になります。

## 3. マルウェアとランサムウェア

マルウェアは、利用者やシステムへ害を与える目的で作られたソフトウェアの総称です。

情報を盗むもの、遠隔操作を可能にするもの、他の端末へ広がるものなどがあります。

ランサムウェアは、データやシステムの利用を妨げ、復旧などと引き換えに金銭を要求する攻撃で使われます。

現在のランサム攻撃では、データの暗号化だけでなく、情報を窃取して公開をちらつかせるなど、複数の方法で圧力をかける事例があります。

バックアップは重要ですが、バックアップだけで侵入や情報窃取を防げるわけではありません。

## 4. 脆弱性の悪用

ソフトウェアには、攻撃に利用できる欠陥が見つかることがあります。

公開された脆弱性について修正版が提供された場合、適切に更新しないと攻撃される危険が残ります。

しかし、更新だけが対策ではありません。

外部へ公開する必要のない機能を閉じること、適切な設定を行うこと、利用状況を把握することも重要です。

## 5. インジェクション

Webアプリケーションなどでは、利用者から受け取った入力を不適切に処理すると、その入力の一部が命令として解釈されることがあります。

これをインジェクションと呼びます。

SQLインジェクションでは、入力値がデータベースへの命令として不正に解釈されることで、情報の閲覧や変更などにつながる可能性があります。

対策では、入力を単純に禁止文字の一覧だけで判断するのではなく、パラメータ化されたクエリなど、命令とデータを分離する安全な実装を使うことが重要です。

## 6. サービス妨害攻撃

DoS攻撃は、システムへ大量の処理を発生させるなどして、正常な利用を妨げる攻撃です。

多数の機器などを利用して行われるものは、DDoS攻撃と呼ばれます。

DDoSへの対策は、単一の設定だけでは十分でないことがあります。

サービスの構成、通信量、提供事業者の防御機能などを組み合わせて考える必要があります。

## 7. 人と技術の両方を見る

多くの攻撃では、人の判断、認証、ソフトウェア、ネットワーク、運用など複数の部分が関係します。

利用者教育だけに責任を置いても十分ではありません。

反対に、技術対策だけで人をだます攻撃を完全に防げるとも限りません。

複数の防御を重ね、どこか一つが突破されても被害を抑える設計が重要です。
