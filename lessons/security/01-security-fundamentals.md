# 1. 情報セキュリティの基本

Status: Draft v0.2  
確認日: 2026-09-27

## 1. 情報セキュリティとは

情報セキュリティは、情報や情報システムを脅威から守り、必要な状態を維持するための考え方と活動です。

代表的な三つの要素として、機密性、完全性、可用性があります。

機密性は、許可された人やシステムだけが情報へアクセスできる状態です。

完全性は、情報や処理が意図しない変更や破壊を受けず、正確性が保たれている状態です。

可用性は、許可された利用者が、必要なときに情報やシステムを利用できる状態です。

この三つは、英語の頭文字からCIAと呼ばれます。

CIAは情報セキュリティを考える代表的な三要素です。

実務では、真正性や責任追跡性など、ほかの性質も扱います。

セキュリティでは、一つだけを最大化すればよいわけではありません。

例えば、誰もアクセスできないようにすれば機密性は高く見えます。しかし、必要な人まで使えなければ可用性が損なわれます。

利用目的に応じて、複数の要素をバランスよく守る必要があります。

## 2. 情報資産

守る対象は、ファイルやデータベースだけではありません。

業務データ、個人情報、認証情報、端末、サーバー、ネットワーク機器、クラウドサービスなども情報資産になり得ます。

さらに、業務手順や設定情報、組織が持つ知識も重要な資産です。

何を守る必要があるかを把握しなければ、適切な対策を選ぶことはできません。

## 3. 脅威と脆弱性

脅威は、情報資産へ悪影響を与える原因になり得るものです。

攻撃者による不正アクセスだけが脅威ではありません。

操作ミス、機器故障、災害、委託先での事故なども脅威になり得ます。

脆弱性は、脅威によって利用される可能性のある弱点です。

ソフトウェアの欠陥だけでなく、弱い設定、不適切な権限、教育不足、運用上の不備も弱点になり得ます。

同じ脅威が存在しても、環境や対策によって実際のリスクは異なります。

## 4. リスクを考える

セキュリティ対策では、すべての危険を完全になくすことは通常できません。

そのため、何が起こり得るか、どの程度起こり得るか、起きた場合にどの程度の影響があるかを考えます。

リスクは一般に、発生する可能性と、その場合の影響の両方を踏まえて評価します。

重要な情報を扱うシステムでは、同じ脆弱性でも影響が大きくなることがあります。

反対に、影響が小さい対象へ過剰な対策を行えば、費用や運用負担が大きくなります。

リスクに応じて対策を選ぶことが重要です。

## 5. セキュリティは継続的に管理する

情報セキュリティは、一度対策すれば終わる作業ではありません。

利用するシステムは変化します。

新しい脆弱性が発見されることがあります。

攻撃手法も変化します。

組織の業務や委託先も変わります。

そのため、状況を把握し、対策し、異常を検知し、問題へ対応し、復旧するという継続的な管理が必要です。

NIST Cybersecurity Framework 2.0では、サイバーセキュリティリスク管理の成果を、Govern、Identify、Protect、Detect、Respond、Recoverという六つの機能で整理しています。

この六つは、最初から最後まで順番に一度だけ実行する手順ではありません。

複数の機能を同時並行かつ継続的に扱います。

これは個別製品の導入手順でもありません。

組織がセキュリティリスク管理の全体像を整理するための枠組みです。
