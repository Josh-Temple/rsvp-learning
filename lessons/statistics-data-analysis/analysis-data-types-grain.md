# データ型・観測単位・粒度

Status: COMPLETE v0.1
Created: 2026-10-31

## 学習目標

カテゴリと数量、識別子と測定値を区別できる。表の一行が表す対象と時点を説明し、行数をそのまま人数や件数と見なせない場合を指摘できる。

## 本文

1. 販売記録に百行あっても、
2. 注文が百件あるとは限りません。
3. 一つの注文で複数の商品を買えば、
4. 商品ごとの行ができます。
5. 逆に、一人の利用者の一か月分を一行にまと
6. めた表もあります。
7. ここでは架空の通販サービスを例に、
8. 数字を計算する前に表の意味を確かめます。
9. 観測単位は、何を一つの対象として記録するかを
10. 示します。
11. 利用者一人、注文一件、
12. 商品明細一件は違う単位です。
13. データの粒度は、どこまで細かく区別しているかと
14. いう詳しさです。
15. 「利用者ごと」だけでなく、
16. 「利用者一人について一日ごと」まで決めると、
17. 一行の意味が明確になります。
18. 変数は、対象ごとに値が変わる特徴です。
19. 配送方法のようなカテゴリと、
20. 購入金額のような数量を区別します。
21. カテゴリのうち、通常便・冷蔵便のように
22. 自然な順序がないものは名義尺度です。
23. 優先度の低・中・高のように順序があるものは
24. 順序尺度ですが、低から中と、
25. 中から高の差が等しいとは限りません。
26. 配送方法を一、二、三で記録しても、
27. その平均が配送方法の「中間」を表すわけでは
28. ありません。
29. 番号は分類のための符号だからです。
30. 満足度の段階も、数字を付けただけで等間隔の量に
31. なるとは限りません。
32. 集計法を選ぶときには、数字の見た目より、
33. 測った内容と置いた仮定を確認します。
34. 数量には、商品の個数のように数える離散値と、
35. 重量や所要時間のように連続的な量があります。
36. 実際の重量を一グラム単位で記録していても、
37. 記録の丸め方と、もとの量の性質は別です。
38. また、金額には通貨、重量には単位が必要です。
39. 千円単位の欄を円として合計すれば、
40. 計算操作が正しくても結果は誤ります。
41. 識別子は、対象を区別するための値です。
42. 利用者番号や注文番号は、
43. 通常は足し算する測定値ではありません。
44. 先頭の零を含むコードを数量として読み込むと、
45. もとの表記を失うことがあります。
46. 注文ごとに一行の表なら、
47. 注文番号で各行を区別できるはずです。
48. 商品明細ごとなら、
49. 同じ注文番号が複数行に現れるのは自然です。
50. その場合は注文番号と明細番号の組などで行を
51. 区別します。
52. 「番号が重なっているから削除する」と決める前に
53. 、想定した粒度で本当に重複しているかを調べます。
54. 注文ごとに同じ合計金額を全明細へ付けた表では、
55. その金額を行ごとに足すと二重計上になります。
56. もとの注文表で集計するか、
57. 注文を一度ずつ数える形へそろえます。
58. 具体的な結合と検査は実務編へ譲り、
59. ここでは「何の一件か」を言葉で確認します。
60. 利用者の住所や注文の状態は変わります。
61. 現在の住所を使うのか、
62. 注文時点の住所を使うのかで、
63. 地域別の結果は違う場合があります。
64. 日付だけの記録と、時刻まである記録も、
65. 同じ精度ではありません。
66. 複数の地域の時刻を扱うなら、
67. どの時間帯の時刻かも必要です。
68. 同じ瞬間でも日付が異なることがあるため、
69. 日別にまとめる基準をそろえます。
70. 通信で使う時刻表現にはUTCとの差を
71. 付ける方法がありますが、
72. 本章で特定形式への一律変換を義務付けるものでは
73. ありません。
74. 表を受け取ったら、一行の対象と期間、
75. 列の意味と単位、行を区別する条件を説明で
76. きるか確かめます。
77. 説明できない表では、
78. 行数が何を数えているかもまだ確定していません。

## 注意

具体例は学習用の架空例です。実務では対象・定義・入力データの版を確認してください。
