# 分析課題の定義と意思決定

Status: COMPLETE v0.1
Created: 2026-10-31

## 学習目標

業務上の判断を分析で調べる問いに直し、対象・比較・必要な記録を説明できる。現在のデータで答えられる問いと、追加の収集や比較設計が必要な問いを区別できる。

## 本文

1. 「申請の受付画面を新しくしたので、改善したか調べてほしい」。
2. この依頼だけで分析を始めると、処理件数、入力時間、利用者の満足度など、違う結果をそれぞれが想定するかもしれません。
3. 以下では、架空の自治体が、新画面を他の手続にも広げるか判断する場面を考えます。
4. 実在の自治体の実績ではありません。
5. 分析課題を定義するとは、何を決めるために、誰や何について、どのような答えを必要とするかを明確にすることです。
6. 「集計表を作る」は作業で、「展開を続けるか」は意思決定です。
7. 作業を終えたことと、判断に必要な証拠が得られたことを分けます。
8. 担当者が知りたいのは、住民の入力の手間なのか、受付後の審査待ちなのかを確認します。
9. 入力画面の改善なら、入力を始めてから提出するまでが直接の対象になります。
10. 審査待ちには受付後の体制も関わるため、新画面だけを見ても答えはそろいません。
11. ここでは「新画面を使った申請で、提出までに止まる場面が減ったか」を調べるとします。
12. 対象の手続と利用期間を定め、入力を始めた申請を追い、途中でやめた申請も含めて調べます。
13. 提出できた人だけに尋ねると、途中で困った人を最初から除いてしまうからです。
14. 集計の式と分母の定義は次章で扱います。
15. 比較も問いの一部です。
16. 「変更前より良いか」と「別の画面より良いか」では相手が違います。
17. 前後比較なら、繁忙期、利用者層、対象手続、支援の有無などが変わっていないかを確認します。
18. 条件がそろわないときは、違いを記録し、比較できる範囲に結論を限定します。
19. 旧画面では提出日時だけ、新画面では入力開始日時も記録しているとします。
20. このままでは、提出までの所要時間を同じ定義で前後比較できません。
21. 欠けている記録を想像で補わず、過去の別記録を探すか、今後同じ方法で記録するか、問いを狭めるかを判断します。
22. 入力画面の所要時間とは別の指標として、受付後の処理日数を考えます。
23. 架空の例で、平均処理日数が十日から七日になったとします。
24. ここから言えるのは、同じ条件で集計できたなら、その対象の平均が三日短くなった、ということまでです。
25. 同時期の人員増や案件構成の変化を除けていない以上、新画面が三日短縮したとは断定できません。
26. さらに、完了案件だけの平均なら、長くかかっている未完了案件は含まれません。
27. 集計時点で完了時刻が未観測の案件を除くと、長い案件を少なく数える偏りが生じることがあります。
28. 完了分の結果と、未完了件数や受付からの経過時間を分けて示します。
29. 未完了の最終所要時間が分かったことにはしません。
30. 問いを具体化したら、答えが違う場合に何をするか考えます。
31. 途中離脱が特定の入力項目へ集中していれば、その項目を直す候補になります。
32. 全体の数字だけでは理由が分からなければ、利用者の操作観察や問い合わせ内容を追加します。
33. 数字だけですべてを決めようとせず、不足する証拠を特定します。
34. 反対に、「今週の問い合わせを分類し、案内文の修正箇所を選ぶ」だけなら、大規模な因果効果の推定が常に必要なわけではありません。
35. 記述で足りる判断もあります。
36. ただし、選んだ修正が問題を解消したかは、その後に別の問いとして確かめます。
37. 分析の前に短く残す記録は、判断する人と選択肢、調べる対象、比較相手、必要な記録、答えられないことです。
38. 結論を先に決める記録ではありません。
39. 途中で問いを変える必要が生じたら、その理由を残し、最初から同じ問いだったように扱わないための記録です。

## 注意

具体的な数値や組織は、特に断りのない限り学習用の例です。実務では対象と条件を確認してください。
