# 統合ケース：行政サービスの改善評価

Status: COMPLETE v0.1
Created: 2026-10-31

## 学習目標

架空の行政サービスのデータについて、対象と測定単位の定義から記述、比較、限界、意思決定まで一連の手順を説明できる。前後の改善を因果効果と断定しない報告を作れる。

## 本文

1. 自治体の申請サービスを改善する架空の案件を考えます。
2. 新しい画面を導入した後、申請の処理が早くなったように見えます。
3. しかし、それだけで新画面が原因だとは言えません。
4. ここでは集計から判断までの道筋を通して確認します。
5. 登場する件数、日数、組織、結果はすべて学習用に作ったもので、実際の自治体の調査結果ではありません。
6. 担当者の判断は「新画面を継続し、他部署へ広げるか」です。
7. 問いたいのは、単に処理件数が増えたかではなく、申請者にとって処理が早くなり、差戻しや問い合わせが増えていないかです。
8. 申請一件を観測単位とし、受付日の後十四日以内に完了した割合を主要な記述指標とします。
9. 申請者一人が複数件出すことや、同じ申請が差戻し後に再登録されることも識別できるようにします。
10. 観測期間の終わりに受け付けた案件は、まだ十四日経っていません。
11. そこで旧画面期間、新画面期間とも、受付から十四日間の追跡が済んだ申請だけを比較する設計とします。
12. 完了しなかった案件も分母へ残します。
13. もちろん追跡できない案件は別途示します。
14. 旧画面の対象が五百件、そのうち十四日以内に完了した案件が三百七十五件だったとします。
15. 割合は三百七十五÷五百で七十五パーセントです。
16. 新画面は五百五十件中四百四十件が完了し、八十パーセント。
17. 差は五パーセントポイントです。
18. これは観測された割合の差であり、画面による効果の推定値と呼ぶには追加の条件が必要です。
19. さらに、受付時に申請区分が欠損している件数、差戻し回数、問い合わせ人数を確認します。
20. 問い合わせ回数を申請者の人数へ読み替えたり、明細結合によって案件数を膨らませたりしてはいけません。
21. 元記録の入力日時、項目定義、分類変更も追跡します。
22. 新画面の時期には、処理の簡単な申請が増えたかもしれません。
23. 応援職員が増えた可能性もあります。
24. 区分別・部署別の記述を確認し、同じ構成の申請を比較しても結果が保たれるかを調べます。
25. 区分をそろえたとしても、未観測の違いは残り得ます。
26. 可能なら新画面を導入しなかった比較部署を同時期に観測しますが、部署の業務が異なればそのまま対照とはみなせません。
27. 無作為割当がなければ、平行トレンドなど評価設計に応じた識別の仮定も検討します。
28. 比較が成立しない場合は、因果効果を特定できないと報告します。
29. 現段階の報告には「十四日以内完了率は七十五パーセントから八十パーセントへ上昇」という観測事実を示します。
30. 同時に、件数・構成の変化、未追跡の有無、問い合わせや差戻しの副作用、データの限界を添えます。
31. 利用者への不利益や情報保護上の問題も確認します。
32. 施策の全面展開をすぐ決めるのではなく、追加の追跡と比較設計を条件に段階導入するという判断もあります。
33. 費用と実施可能性、現場の報告を合わせて決めます。
34. 分析は意思決定を支えますが、記述上の差を因果効果へすり替えることはできません。

## 注意

具体的な数値や組織は、特に断りのない限り学習用の例です。実務では対象と条件を確認してください。
