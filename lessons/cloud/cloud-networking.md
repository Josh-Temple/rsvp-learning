# クラウドネットワークの基本

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

仮想ネットワーク、公開・非公開の境界、通信制御の基本を学びます。

## 本文

1. 利用者のブラウザから公開入口へ届いた要求が、アプリを経てデータベースへ進むとします。
2. データベースを直接公開する必要はありません。
3. クラウドでも、ネットワークの基本は変わりません
4. システム同士は、ネットワークを通じて通信します
5. 仮想ネットワークは、クラウド上に論理的な通信範囲を作ります
6. サブネットで、ネットワークを複数の範囲へ分けられます
7. 外部公開が必要な部分と、内部だけで使う部分を分けます
8. データベースを直接インターネットへ公開しない設計が一般的です
9. FirewallやSecurity Groupなどで通信を制御します
10. 必要な宛先とポートだけを許可します
11. DNSは、名前と接続先を対応づけます
12. Load Balancerは、複数の処理先へ通信を分散します
13. 公開入口とデータベースを同じ到達範囲に置く必要はありません。
14. 通信経路を複雑にすると、障害調査も難しくなります
15. ネットワーク設計では、到達性と安全性を両方考えます
16. 通信ログは、問題調査に役立ちます
17. まずは、利用者からアプリ、データベースまでの経路を説明できるようにします
18. 入口からアプリ、アプリからデータベースの通信だけを許す設計を考えます。
19. 名前解決、暗号化、通信制御のどこで失敗したかを切り分けます。
20. 経路を図にして許可元と宛先を点検します。
21. 通信を許す理由を経路ごとに記せば、障害調査と不要な公開の発見に使えます。
22. アプリからDBへつながらなくなったとします。
23. 名前解決、通信許可、接続先を順に確認します。
24. 入口が開くことは内部経路の証明になりません。
25. 画面だけ見てDB停止と断定できますか。
26. 経路ごとの失敗を切り分けます。

## 注意

この章は基礎理解用です。
特定クラウド事業者、特定LLM、特定フレームワークの最新仕様を説明する教材ではありません。
製品固有の仕様や現在の制約は、利用時点の公式資料で確認します。
