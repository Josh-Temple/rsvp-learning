# IPアドレス・パケット・ルーティング

Status: COMPLETE v0.1
Created: 2026-09-29

## 学習目標

IPアドレスとネットワークプレフィックス、パケット、ルータ、経路表、デフォルトゲートウェイの役割を区別し、端末から遠隔サーバーまでパケットが転送される流れを説明できるようにします。

## 本文

1. 通信は小さな単位に分けて送ります。
2. IPではパケットとして運びます。
3. 宛先IPを見て転送します。
4. IPアドレスは配送先の手掛かりです。
5. 人そのものの識別子ではありません。
6. 同じ端末でも複数IPを持てます。
7. ネットワーク部をプレフィックスで表します。
8. 同じ範囲かを判断できます。
9. 近い宛先なら直接届く場合があります。
10. 遠い宛先ならルータへ渡します。
11. ルータは次の転送先を選びます。
12. 経路表を使って判断します。
13. より具体的な経路を優先します。
14. 該当経路がない場合もあります。
15. デフォルト経路を使う場合があります。
16. 端末ではゲートウェイを使います。
17. 各ルータが次の一歩を決めます。
18. 最終経路を一台で決めるとは限りません。
19. パケットごとに独立して扱われます。
20. 到着順はIPだけでは保証しません。
21. 欠落の回復もIPの役割ではありません。
22. 上位プロトコルが補う場合があります。
23. 経路は往復で同じとは限りません。
24. 片方向だけ届く障害もあります。
25. アドレスが正しくても届くとは限りません。
26. 経路がなければ転送できません。
27. 経路があっても途中で落ち得ます。
28. リンク障害も影響します。
29. MTUの違いも影響し得ます。
30. IPv4とIPv6は表現が違います。
31. ただし配送の基本発想は共通です。
32. 名前とIPは別の概念です。
33. DNSが名前をIPへ対応づけます。
34. IPは名前解決後の配送に使われます。
35. ポートもIPとは別です。
36. IPはホスト側の宛先を表します。
37. ポートはサービス側を区別します。
38. ブラウザ通信もIPの上を通ります。
39. 経路を見ると障害箇所を絞れます。
40. 端末自身の設定を確認します。
41. プレフィックスも確認します。
42. ゲートウェイも確認します。
43. 宛先までの途中経路も考えます。
44. 一つの層だけで判断しません。
45. 名前解決と経路を分けて診断します。
46. 通信失敗の原因を層ごとに見ます。
47. まず配送の仕組みを押さえます。
48. その上にTCPなどが乗ります。

## 注意

この章はIP通信の概念理解用です。IPv4とIPv6には仕様上の違いがあり、実際のアドレス設計、経路制御、NAT、MTUなどの詳細は利用環境と最新仕様を確認します。
