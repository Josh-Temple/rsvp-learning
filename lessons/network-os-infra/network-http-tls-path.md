# HTTP・TLSとブラウザからサーバーまで

Status: COMPLETE v0.1
Created: 2026-09-29

## 学習目標

HTTPの要求・応答、Method、Status、Header、Bodyと、TLSの暗号化・完全性・相手確認を区別し、ブラウザからサーバーまでの代表的な通信経路を段階ごとに説明できるようにします。

## 本文

1. ブラウザはURLを解釈します。
2. まず接続先の名前を扱います。
3. DNSでIPを得る場合があります。
4. 次に通信経路を作ります。
5. HTTP1や2はTCPを使う場合があります。
6. HTTP3はQUICを使います。
7. 下位方式は一つではありません。
8. HTTPSではTLSを使います。
9. TLSは通信を暗号化します。
10. 改ざん検知にも関わります。
11. 相手の証明書も確認します。
12. 証明書は名前との関係を見ます。
13. TLS成功とサイト信頼性は別です。
14. 通信路が保護されたことを示します。
15. HTTPは要求と応答で動きます。
16. ClientがRequestを送ります。
17. ServerがResponseを返します。
18. Methodが操作意図を表します。
19. GETは取得に使われます。
20. POSTは処理送信に使われます。
21. Statusは結果の分類を示します。
22. Headerは付加情報を持ちます。
23. Bodyは内容を持てます。
24. HTTPは基本的にStatelessです。
25. 状態は別仕組みで補う場合があります。
26. Cookieなどが使われます。
27. Proxyが途中に入る場合があります。
28. CDNが応答する場合もあります。
29. Load Balancerも構成要素です。
30. 接続先が一台とは限りません。
31. TLS終端位置も構成で変わります。
32. HTTPエラーと接続失敗は別です。
33. 404はHTTP応答が返っています。
34. Timeoutは段階を確認します。
35. DNSで止まる場合があります。
36. TCPで止まる場合があります。
37. TLSで止まる場合があります。
38. HTTP処理で止まる場合があります。
39. 502などは中継側も関係します。
40. ブラウザ画面だけで原因を決めません。
41. HTTPSなら内容も正しいですか。
42. 暗号化と正当性は別です。
43. 証明書が有効でもアプリは誤れます。
44. 各層の役割を分けます。
45. 再利用接続なら一部手順を省けます。
46. Cacheでも通信が変わります。
47. 代表的な流れとして理解します。
48. 実際の構成は観測して確かめます。

## 注意

この章はWeb通信の基礎です。HTTP/1.1、HTTP/2、HTTP/3は下位の通信方式が異なり、CDN、Proxy、Load Balancerなどの構成も環境によって異なります。
