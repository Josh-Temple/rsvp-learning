# TCP・UDP・Portと通信の単位

Status: COMPLETE v0.1
Created: 2026-09-29

## 学習目標

TCPとUDPが提供する通信特性を区別し、PortとSocketがアプリケーションの通信先をどう表すか、接続できることとアプリケーションが正常であることが別である理由を説明できるようにします。

## 本文

1. IPの上でアプリ通信を運びます。
2. TCPとUDPが代表例です。
3. TCPは接続を作って通信します。
4. 順序を保つ仕組みがあります。
5. 欠落を検知して再送します。
6. 確認応答を使います。
7. 流量も調整します。
8. 混雑も考慮します。
9. TCPはバイト列を運びます。
10. メッセージ境界は保持しません。
11. アプリ側で区切りが必要です。
12. 接続開始には状態があります。
13. 終了にも状態があります。
14. 接続が残る場合もあります。
15. UDPはデータグラムを送ります。
16. 接続確立なしで送れます。
17. 順序保証は組み込みません。
18. 再送保証も組み込みません。
19. 必要なら上位で補えます。
20. UDPだから不安定とは限りません。
21. 用途に合う設計が重要です。
22. Portはサービスを区別します。
23. 同じIPで複数サービスを扱えます。
24. 宛先Portで相手側を選びます。
25. 送信元Portも使います。
26. Client側は動的Portを使えます。
27. IANAがPort番号を管理します。
28. 番号だけで安全性は決まりません。
29. Socketは通信端点を表します。
30. IPとPortを組み合わせます。
31. TCPでは接続ごとに状態を持ちます。
32. 同じPortでも複数接続できます。
33. 接続成功はアプリ正常を意味しません。
34. 待受中でも処理失敗はあり得ます。
35. Portが閉じていれば接続できません。
36. 途中の制御で遮断もあり得ます。
37. Timeoutの原因は複数あります。
38. 名前解決とは別に確認します。
39. TCP接続とも別に確認します。
40. HTTP応答とも別に確認します。
41. 各段階を分けて診断します。
42. WebでもTCPとは限りません。
43. HTTP3はQUICを使います。
44. QUICはUDP上で動きます。
45. 信頼性機能を上位で持ちます。
46. プロトコル階層を意識します。
47. Portは入口の一部です。
48. アプリの意味はさらに上位です。

## 注意

この章はトランスポート層の基礎です。QUICなどUDP上に独自の信頼性や暗号化を持つプロトコルもあり、TCP対UDPを単純な『信頼できる／できない』だけで分類しません。
