# 同期・非同期・イベント・Queue

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

処理を待つ同期方式と、Queueやイベントを使う非同期方式の違いを学びます。

## 本文

1. 申請受付と同時に通知を送る設計では、通知先が遅いと画面の応答も遅くなります。
2. 受付を先に確定し、通知をキューへ渡すと画面は早く返せます。
3. 同期処理では、相手の処理結果を待ちます
4. 処理の流れを理解しやすいことが利点です
5. ただし、相手が遅いと全体も待つことになります
6. 非同期処理では、依頼後に別の処理へ進めます
7. 時間のかかる処理を切り離せます
8. Queueは、処理要求を一時的に保存して受け渡します
9. 送信側と受信側を、時間的に分離できます
10. イベントは、何かが起きたことを表します
11. イベントを受けて別の処理を動かす設計があります
12. 非同期では、処理完了のタイミングが分かりにくくなります
13. 通知を後回しにすると受付画面は早く返せますが、通知の完了は別の時点になります。
14. 重複処理や順序入れ替わりも考える必要があります
15. 失敗したメッセージの扱いも設計します
16. 監視と追跡可能性が重要になります
17. 非同期化は、性能だけでなく依存を緩めるためにも使われます
18. ただし通知は後で失敗し、重複して届く可能性があります。
19. 受付番号で同じ通知を識別し、再試行と失敗時の調査方法を決めます。
20. 受付成功と通知成功を別の状態として扱います。
21. 受付と通知の状態を分け、再試行で同じ通知が増えないよう識別します。

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
