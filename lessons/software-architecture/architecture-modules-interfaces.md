# モジュールとインターフェース

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

システムを責務ごとに分け、部品同士の接点を明確にする基本を学びます。

## 本文

1. 受付機能が申請を保存し、通知機能が受付番号を送るとします。
2. 二つを分けるなら、通知へ渡す受付番号、宛先、時刻を決めます。
3. 大きなシステムは、役割ごとの部品へ分けて考えます
4. モジュールは、関連する責務をまとめた単位です
5. 一つのモジュールに多くの責務を詰め込みすぎないようにします
6. 責務が明確だと、変更範囲を限定しやすくなります
7. インターフェースは、部品同士の接点です
8. 何を受け取り、何を返すかを定めます
9. 内部実装を知らなくても利用できる形が望まれます
10. インターフェースを安定させると、内部変更の影響を減らせます
11. データ形式やエラー条件も、接点の一部です
12. 責務の境界が曖昧だと、同じ処理が複数箇所へ広がります
13. 受付を保存する責務と、通知を届ける責務を分けても、受付番号の受け渡しは残ります。
14. 共通処理を分ける場合も、責務を確認します
15. 細かく分けすぎると、連携が複雑になります
16. 分割には、適切な粒度が必要です
17. 設計では、責務と接点を説明できることが重要です
18. 通知が失敗しても申請自体を消すのか、後で再送するのかを明確にします。
19. 境界を越えるデータの型と責任を揃えます。
20. 独立した部品でも全体の動きを試験します。
21. 境界で渡す値と失敗時の扱いを決めて初めて、二つの部品を安全につなげられます。

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
