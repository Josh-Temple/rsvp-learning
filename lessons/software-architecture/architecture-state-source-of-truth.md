# 状態管理とSingle Source of Truth

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

複数の場所に状態を持つ難しさと、正本を明確にする設計の基本を学びます。

## 本文

1. 状態は、システムが現在どの状況にあるかを表します
2. 例えば、申請中、承認済み、取消済みなどがあります
3. 同じ状態を複数の場所で管理すると、ずれが起こることがあります
4. どの情報について、どこを正本とするかを決めます
5. Single Source of Truthは、特定の情報について、正しい値を参照する基準を定める考え方です
6. 他の画面や集計表は、正本から派生させます
7. 派生データは、遅れて更新される場合があります
8. その場合、どの程度の遅延を許すか考えます
9. 状態変更には、権限と条件を設けることがあります
10. 不正な順序で状態が変わらないようにします
11. 履歴を残すと、後から変化を追えます
12. 更新が途中で失敗した場合の扱いも決めます
13. 状態と履歴を混同しないことが重要です
14. 正本と派生情報を区別すると、復旧しやすくなります

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
