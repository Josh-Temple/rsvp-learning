## 目的

この章は「ソフトウェア設計・アーキテクチャ」の入口です。

後続章を作るための骨格として置きます。

## 最初に押さえること

- ソフトウェア設計では、責務を分けることが重要です
- モジュールは、関連する処理をまとまりとして扱います
- インターフェースは、部品同士の接点を定めます
- 依存関係が増えるほど、変更の影響範囲は広がります
- 状態は、システムが現在どの段階にあるかを表します
- 同期処理は結果を待ち、非同期処理は待たずに進められます
- キューは、処理要求を順番に受け渡すために使われます
- イベント駆動では、出来事をきっかけに処理します
- Single Source of Truthは、正しい情報の基準を一つに定めます
- 冪等性は、同じ処理を繰り返しても結果が壊れない性質です
- Retryには、重複や副作用への対策が必要です
- まずは、責務、状態、失敗時の挙動を説明できることを目標にします
