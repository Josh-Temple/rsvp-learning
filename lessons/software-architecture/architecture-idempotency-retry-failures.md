# 冪等性・Retry・失敗時の挙動

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

分散システムで避けにくい失敗に備え、再試行しても壊れにくい設計を学びます。

## 本文

1. 外部通信を含む処理は、途中で失敗することがあります
2. 失敗したか成功したか分からない場合もあります
3. そのとき、同じ処理を再試行することがあります
4. Retryは、一時的な失敗から回復する方法の一つです
5. ただし、無制限のRetryは負荷を増やします
6. 一定時間を空けて再試行する方法があります
7. 冪等性とは、同じ要求を何度繰り返しても、意図した効果が一回の実行と同じになる性質です
8. 二重登録や二重送信を防ぐために重要です
9. 処理IDを使って重複を検出する方法があります
10. 失敗時に、部分的な更新が残らないように考えます
11. すべてを元に戻せない処理もあります
12. その場合は、補償処理を設計することがあります
13. 失敗を隠すのではなく、状態として表現することも重要です
14. 復旧手順まで含めて、正常な設計と考えます
15. 利用者が送信ボタンを押した後、応答だけが途切れたとします。
16. 処理が成功したか不明なまま再送すると二件登録されるおそれがあります。
17. 申請ごとに同じ識別子を使い、既に処理済みなら同じ結果を返す設計にします。
18. 識別子の有効期間と異なる内容での再利用も決めます。
19. 失敗した場所ごとに再試行の可否を分けます。

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
