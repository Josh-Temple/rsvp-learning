# ガバメントクラウドと責任分界・運用

Status: COMPLETE v0.1
Created: 2026-09-29

## 学習目標

クラウド事業者と行政・運用事業者の責任を分け、可用性、監視、IAM、バックアップ、コスト、障害対応、Exitを一体として設計する必要性を説明できるようにします。

## 本文

1. クラウド利用は移設だけではありません。
2. 運用設計も変わります。
3. 責任分界を確認します。
4. Cloud事業者の責任があります。
5. 利用組織の責任も残ります。
6. 設定責任を曖昧にしません。
7. IAMを設計します。
8. 管理者権限を絞ります。
9. 利用者権限も最小化します。
10. Service Accountも管理します。
11. Logを集めます。
12. 監視対象を決めます。
13. 可用性要件を定めます。
14. 冗長化だけで十分とは限りません。
15. 依存Serviceも確認します。
16. Backupを設計します。
17. 復元試験も行います。
18. 保存しているだけでは不十分です。
19. RTOを考えます。
20. RPOも考えます。
21. 障害時の連絡経路を決めます。
22. 責任者を明確にします。
23. 事業者間の境界もあります。
24. アプリ事業者も関係します。
25. 運用事業者も関係します。
26. 障害切り分けを準備します。
27. 変更管理も必要です。
28. 設定変更を記録します。
29. IaCを使う場合もあります。
30. 再現性を高められます。
31. Costも継続監視します。
32. 使った分だけ安いとは限りません。
33. 過剰資源を見直します。
34. Data Transfer費もあり得ます。
35. Managed Serviceも費用があります。
36. 運用工数も合わせて見ます。
37. Lock-inも評価します。
38. ただし抽象化には費用があります。
39. Exit Planを持ちます。
40. Data Exportを確認します。
41. 設定情報も引き継ぎます。
42. 暗号鍵も管理します。
43. 契約終了時を想定します。
44. Cloud Native化が目的ではありません。
45. 公共サービスの価値が目的です。
46. 標準準拠と運用最適化を分けます。
47. 移行後も継続して改善します。
48. 責任と観測を明確にします。

## 注意

ガバメントクラウドの利用条件、推奨構成、対象システム、費用負担、責任分界は最新のデジタル庁資料と契約・運用設計を確認します。クラウド利用だけで安全性や低コストが自動的に保証されるわけではありません。
