# 開発ライフサイクル

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

企画から運用保守まで、システム開発の工程と各工程の目的を学びます。

## 本文

1. 小さな申請システムでも、目的の整理から要件、設計、実装、試験、運用まで続きます。
2. 公開した時点で終わりではなく、制度改正時に案内を直す必要があります。
3. システム開発は、複数の工程で進みます
4. 企画では、解くべき課題と投資目的を整理します
5. 要件定義では、実現すべき条件を決めます
6. 設計では、要件を実装可能な構造へ落とします
7. 実装では、コードや設定として形にします
8. テストでは、期待どおり動くか確認します
9. 移行では、旧環境から新環境へ切り替えます
10. リリース後は、運用と保守が始まります
11. 障害対応だけが、運用ではありません
12. 監視、問い合わせ、改善も運用に含まれます
13. 公開後に制度が変われば、要件と案内を直し、試験してから反映します。
14. 前工程の曖昧さは、後工程で大きな手戻りになり得ます
15. 一方で、すべてを最初に確定できるとは限りません
16. 工程ごとの目的と成果物を理解することが重要です
17. 全体像を持つと、自分の担当の位置づけが見えます
18. 各段階の成果を次の段階へ渡し、利用者の確認を受けます。
19. 不具合の報告があれば原因を調べ、修正後に回帰を試験します。
20. 保守の担当と費用を計画に含めます。
21. 企画時に保守の担当と費用を考えるのは、公開後も価値を保つためです。
22. 公開後、代理人の必要書類が変わったとします。
23. 案内文だけ直すと、入力チェックが古いままです。
24. 要件から試験まで変更の影響をたどります。
25. 公開後の変更を単なる文言修正としてよいですか。
26. 動作と運用への影響も確認します。

## 次に確認したいこと

この章は基礎理解用です。
具体的な製品仕様、組織固有の工程名、法令上の要件は、この章だけで確定しません。
必要に応じて公式資料・一次資料で確認します。
