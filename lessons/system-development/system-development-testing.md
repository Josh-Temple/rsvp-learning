# テストの基本

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

単体、結合、システム、受入テストの役割と、テスト設計の基本を学びます。

## 本文

1. 申請期限の計算を単体テストで確かめ、画面とAPIの接続を結合テストで確かめます。
2. 受入テストでは利用者が一件の申請を完了できるか見ます。
3. テストは、期待どおり動くかを確認する活動です
4. 単体テストは、小さな部品を確認します
5. 結合テストは、複数の部品の連携を確認します
6. システムテストは、システム全体を確認します
7. 受入テストは、利用者側の要求を満たすか確認します
8. 工程名や範囲は、組織によって異なることがあります
9. テストケースは、確認する条件と期待結果を定めます
10. 正常系だけでは不十分です
11. 異常入力や境界値も確認します
12. 権限による違いもテスト対象です
13. 期限計算の単体試験だけでは、画面から申請が完了するか分かりません。
14. 非機能要件には、性能や可用性のテストがあります
15. 不具合は、再現条件を明確にして管理します
16. 要件からテストまで追えることが重要です
17. テストは、品質を作る最後の工程ではなく、品質を確認する工程です
18. 各試験で見つかる不具合は異なるため、一つが通っても他を省けません。
19. 通常の入力に加え、期限ぎりぎりと書類不足も試します。
20. 期待結果を要件に結びます。
21. 連携と受入の試験を要件につなぎ、どの段階でどの問題を見つけるか整理します。
22. 期限計算が正しくても、APIが拒否するとします。
23. 単体試験だけでは申請を完了できません。
24. 結合試験で接続を、受入試験で目的を見ます。
25. 一段階の試験が通れば十分でしょうか。
26. 異なる失敗を拾うため、段階を分けます。

## 次に確認したいこと

この章は基礎理解用です。
具体的な製品仕様、組織固有の工程名、法令上の要件は、この章だけで確定しません。
必要に応じて公式資料・一次資料で確認します。
