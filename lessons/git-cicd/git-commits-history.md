# Commitと履歴

Status: DRAFT v0.1
Created: 2026-09-27

## 学習目標

Gitのcommitが何を記録し、変更履歴をどう追跡するかを学びます。

## 本文

1. Gitは、ファイルの変更履歴を管理します
2. Commitは、ある時点の変更を記録します
3. Commitには、識別するためのハッシュがあります
4. 変更内容だけでなく、親となるCommitも記録します
5. このつながりが、履歴を作ります
6. Commit messageには、変更理由が分かる情報を残します
7. 一つのCommitに無関係な変更を混ぜすぎないようにします
8. 小さすぎるCommitも、履歴を読みにくくする場合があります
9. diffを見ると、前後で何が変わったか確認できます
10. 履歴から、いつ誰が変更したか追えます
11. 過去の状態を参照できます
12. 問題の原因となった変更を探す助けになります
13. Gitの履歴は、単なるバックアップではありません
14. 変更の意図を残す記録として使います

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
