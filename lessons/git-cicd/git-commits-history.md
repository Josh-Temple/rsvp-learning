# Commitと履歴

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

Gitのcommitが何を記録し、変更履歴をどう追跡するかを学びます。

## 本文

1. 申請画面の文言修正と計算処理の変更を一つのコミットに混ぜたとします。
2. 不具合が出た際に、どの変更を戻すべきか判断しづらくなります。
3. Gitは、ファイルの変更履歴を管理します
4. Commitは、その時点のファイル状態をスナップショットとして記録します
5. Commitには、識別するためのハッシュがあります
6. 変更内容だけでなく、親となるCommitも記録します
7. このつながりが、履歴を作ります
8. Commit messageには、変更理由が分かる情報を残します
9. 一つのCommitに無関係な変更を混ぜすぎないようにします
10. 小さすぎるCommitも、履歴を読みにくくする場合があります
11. diffを見ると、前後で何が変わったか確認できます
12. 履歴から、いつ誰が変更したか追えます
13. 文言修正と計算変更を分ければ、問題の原因と戻す対象を追いやすくなります。
14. 過去の状態を参照できます
15. 問題の原因となった変更を探す助けになります
16. Gitの履歴は、単なるバックアップではありません
17. 変更の意図を残す記録として使います
18. 目的ごとに小さくコミットし、理由が分かるメッセージを付けます。
19. 履歴を見れば変更の順序と意図を追えます。
20. 小ささ自体が目的ではなく、一つの意味のある変更として確かめます。
21. コミットの単位は行数ではなく、ひとつの目的として説明し検証できるかで決めます。
22. ひとつの修正が複数ファイルにまたがります。
23. 意味が一つなら、一つのコミットにできます。
24. 変更理由と確認方法を説明できる単位にします。
25. ファイルごとに必ず分けますか。
26. 目的で区切り、行数で決めません。

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
