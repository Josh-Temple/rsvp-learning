# Pull Request・Review・Issue

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

GitHubで変更を提案し、レビューし、課題を追跡する基本を学びます。

## 本文

1. 申請画面の不具合をIssueに記録し、再現手順と期待する動作を書きます。
2. 修正ブランチのPRで差分とテスト結果を示します。
3. Pull Requestは、変更を統合するための提案です
4. 変更内容を、差分として確認できます
5. 目的や背景を説明する文章も重要です
6. Reviewでは、コードや設計の問題を確認します
7. 動作だけでなく、保守性や安全性も見ます
8. コメントは、具体的な変更箇所へ付けられます
9. 承認条件を、チームで決めることがあります
10. Issueは、課題や要望を記録するために使えます
11. 一つのIssueからPull Requestへつなげる運用もあります
12. 何を完了条件とするか明確にします
13. Issueの再現条件からPRの試験へつなぐと、何を直したか追えます。
14. 大きな変更は、小さなPull Requestへ分けると確認しやすくなります
15. 自動テストの結果も、Review材料になります
16. Review履歴は、意思決定の記録にもなります
17. GitHubは、コードだけでなく変更管理の場として使えます
18. レビューで別の入力条件を指摘されたら修正し、再度確認を受けます。
19. PRをマージする前に、Issueの完了条件を満たしたか確かめます。
20. 議論とコードの変更が対応するようにリンクを残します。
21. テスト通過だけで完了にせず、レビューで見つかった別条件と元の完了条件も確かめます。

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
