# Pull Request・Review・Issue

Status: DRAFT v0.1
Created: 2026-09-27

## 学習目標

GitHubで変更を提案し、レビューし、課題を追跡する基本を学びます。

## 本文

1. Pull Requestは、変更を統合するための提案です
2. 変更内容を、差分として確認できます
3. 目的や背景を説明する文章も重要です
4. Reviewでは、コードや設計の問題を確認します
5. 動作だけでなく、保守性や安全性も見ます
6. コメントは、具体的な変更箇所へ付けられます
7. 承認条件を、チームで決めることがあります
8. Issueは、課題や要望を記録するために使えます
9. 一つのIssueからPull Requestへつなげる運用もあります
10. 何を完了条件とするか明確にします
11. 大きな変更は、小さなPull Requestへ分けると確認しやすくなります
12. 自動テストの結果も、Review材料になります
13. Review履歴は、意思決定の記録にもなります
14. GitHubは、コードだけでなく変更管理の場として使えます

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
