# CIと自動テスト

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

変更ごとにテストや検査を自動実行するCIの役割を学びます。

## 本文

1. 申請画面の入力チェックを直した変更をPRへ出すとします。
2. CIで構文検査と自動テストが動き、誤った入力を通す回帰が見つかれば失敗します。
3. CIは、Continuous Integrationの略です
4. 変更を頻繁に統合し、問題を早く見つける考え方です
5. コードをpushしたときに、自動処理を実行できます
6. 自動テストは、代表的なCI処理です
7. Lintや型検査を実行することもあります
8. Buildが成功するか確認できます
9. Pull RequestごとにCIを動かす運用があります
10. 失敗した変更を、mainへ入れないための条件にできます
11. 自動化すると、同じ検査を毎回同じ条件で行えます
12. 一方で、自動テスト自体にも不具合はあり得ます
13. PRのテストが失敗したときは、変更がどの条件を壊したかを再現できます。
14. 不安定なテストは、判断を難しくします
15. 実行時間が長すぎると、開発速度へ影響します
16. 重要な検査から自動化します
17. CIは、問題を早い段階で発見する仕組みです
18. 修正を追加した後、同じ検査が通ったか確認します。
19. テスト成功は実機での見やすさや仕様の妥当性まで保証しません。
20. 人のレビューと必要な環境での確認も残します。
21. 自動検査に含まれない操作や端末の見え方は、通過したという結果だけでは確かめられません。
22. 構文検査だけを通った変更を考えます。
23. 正しい文法でも、入力条件を壊す場合があります。
24. 検査が何を確認したか明示します。
25. CI成功は全機能の正しさを示しますか。
26. 範囲外の試験も残ります。

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
