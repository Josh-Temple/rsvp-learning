# CIと自動テスト

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

変更ごとにテストや検査を自動実行するCIの役割を学びます。

## 本文

1. CIは、Continuous Integrationの略です
2. 変更を頻繁に統合し、問題を早く見つける考え方です
3. コードをpushしたときに、自動処理を実行できます
4. 自動テストは、代表的なCI処理です
5. Lintや型検査を実行することもあります
6. Buildが成功するか確認できます
7. Pull RequestごとにCIを動かす運用があります
8. 失敗した変更を、mainへ入れないための条件にできます
9. 自動化すると、同じ検査を毎回同じ条件で行えます
10. 一方で、自動テスト自体にも不具合はあり得ます
11. 不安定なテストは、判断を難しくします
12. 実行時間が長すぎると、開発速度へ影響します
13. 重要な検査から自動化します
14. CIは、問題を早い段階で発見する仕組みです
15. 申請画面の入力チェックを直した変更をPRへ出すとします。
16. CIで構文検査と自動テストが動き、誤った入力を通す回帰が見つかれば失敗します。
17. 修正を追加した後、同じ検査が通ったか確認します。
18. テスト成功は実機での見やすさや仕様の妥当性まで保証しません。
19. 人のレビューと必要な環境での確認も残します。

## 注意

この章は基礎理解用です。
実務で判断するときは、対象システムの仕様、組織ルール、データの前提を別途確認します。
