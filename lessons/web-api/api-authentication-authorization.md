# 認証と認可

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

申請APIの例で、認証と認可の違い、対象ごとの権限確認、トークンとOAuthの役割を学びます。

## 本文

1. 申請を扱うAPIに、利用者Aがログインした場面を考えます。
2. 本人確認を行うのが認証です。
3. Aが自分の申請を読む権限を持つか決めるのが認可です。
4. ログインできても、別の利用者Bの申請まで読めるとは限りません。
5. APIは、申請IDが変わっても毎回権限を確かめます。
6. 画面でボタンを隠すだけでは、直接のAPI呼び出しを防げません。
7. 本人確認には、パスワードや多要素認証などを利用できます。
8. 認証後の状態は、セッションなどで維持できます。
9. アクセストークンは、保護された資源へアクセスする認可情報を表します。
10. トークンが届いたら、有効性と用途、権限の範囲を確認します。
11. トークンの存在だけで、任意の申請へのアクセスを許してはいけません。
12. 利用者の役割だけでなく、対象申請との関係も確認します。
13. 例えば、担当職員は担当案件だけを更新できる設計が考えられます。
14. 必要な操作だけを許すのが最小権限の考え方です。
15. OAuthは、別のアプリへ限定したアクセスを委任する枠組みです。
16. 例えば、予定表アプリに読み取りだけを許す場面があります。
17. OAuthのアクセストークンを得たことと、利用者の本人確認は同じ意味ではありません。
18. APIキーは、呼び出し元の識別などに使われることがあります。
19. APIキーがあるだけで、最終利用者まで認証したとは言えません。
20. 秘密情報をソースコードへ直接埋め込まず、漏えい時の失効も考えます。
21. 権限不足なら、情報を返さずにアクセスを拒否します。
22. 重要なのは、誰が、どの対象へ、何をできるかを個別に判断することです。
23. 本人確認済みのAが、Bの申請IDを指定します。
24. 有効な認証情報があっても閲覧は許されません。
25. 対象の所有者と操作権限を毎回確認します。
26. ログイン済みなら全件を読めますか。
27. 認証と対象ごとの認可は別です。
