# 認証と認可

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

申請APIの例で、認証と認可を分け、利用者・対象資源・操作ごとの権限確認、MFA、トークン、OAuth、APIキーの役割の違いを学びます。

## 本文

1. 申請APIへ利用者Aが入るとします。
2. 本人確認を行うのが認証です。
3. Aが何をできるか決めるのが認可です。
4. 認証と認可は別の判断です。
5. ログイン済みでも全件は読めません。
6. 対象ごとに権限を確認します。
7. 誰が何へ何をするかで考えます。
8. 画面でボタンを隠すだけでは不十分です。
9. API側でも必ず認可します。
10. パスワードは認証手段の一つです。
11. 多要素認証も認証を強めます。
12. ただし認可範囲は別に決めます。
13. セッションは認証状態を保てます。
14. アクセストークンも利用されます。
15. トークンの有効性を確認します。
16. 用途と権限の範囲も確認します。
17. トークンがあるだけでは足りません。
18. 対象資源との関係も確認します。
19. 担当職員は担当案件だけとします。
20. これは対象単位の認可です。
21. 最小権限では必要な操作だけ許します。
22. OAuthはアクセス委任の枠組みです。
23. 別アプリへ限定権限を渡せます。
24. OAuthだけで本人確認とは限りません。
25. APIキーは呼出元識別に使えます。
26. 最終利用者の認証とは限りません。
27. 秘密情報をコードへ埋め込みません。
28. 漏えい時に失効できる設計にします。
29. AがBの申請IDを指定するとします。
30. 認証済みでも閲覧は許されません。
31. 所有関係と操作権限を確認します。
32. MFA済みなら全件を読めますか。
33. 強い認証と広い認可は別です。
34. 各リクエストで境界を守ります。

## 注意

この章は基礎理解用です。具体的な認証方式、トークン形式、権限モデルは利用する仕様とシステム設計を確認します。
