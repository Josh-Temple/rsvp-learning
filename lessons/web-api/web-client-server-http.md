# クライアント・サーバーとHTTP

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

ブラウザなどのクライアントとサーバーがHTTPで通信する基本構造を学びます。

## 本文

1. ブラウザで申請一覧を開くと、クライアントがサーバーへHTTP要求を送ります。
2. サーバーは認証と権限を確認してからデータを返します。
3. Webシステムでは、クライアントとサーバーが通信します
4. ブラウザは、代表的なクライアントです
5. サーバーは、要求を受けて処理し、応答を返します
6. HTTPは、Webで広く使われる通信の仕組みです
7. クライアントは、HTTP Requestを送ります
8. サーバーは、HTTP Responseを返します
9. URLは、アクセスする資源の場所を示します
10. GETは、情報取得に使われることが多いです
11. POSTは、新しい処理や登録に使われることが多いです
12. PUTやPATCHは、更新に使われることがあります
13. ブラウザがURLを開くと、サーバーへの要求と返された応答が画面表示につながります。
14. DELETEは、削除を表すために使われます
15. Status Codeは、処理結果の種類を示します
16. Headerは、通信に関する追加情報を持ちます
17. Bodyは、送受信するデータ本体を持つことがあります
18. 画面に表示される情報は、送られた応答をブラウザが処理した結果です。
19. 通信に失敗した場合と、サーバーがエラーを返した場合を分けます。
20. URLを知っているだけで他人のデータを見られない設計にします。
21. 通信失敗と権限による拒否は原因が違うため、どの段階で止まったか分けて調べます。
22. 応答が成功でも、他人の申請が含まれたとします。
23. 通信と表示が動くことは、権限の正しさと別です。
24. サーバーで対象ごとの閲覧権限を確認します。
25. 画面で隠せば情報を守れるでしょうか。
26. 返すデータ自体を制限します。
