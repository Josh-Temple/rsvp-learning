# Webhookと非同期処理

Status: COMPLETE v0.1
Created: 2026-09-27

## 学習目標

イベント通知、Webhook、Queueなどを使う非同期処理の基本を学びます。

## 本文

1. 審査完了時に外部システムへWebhookを送るとします。
2. 受信側が一時的に停止していれば、後で再送する必要があります。
3. 同期処理では、処理結果を待ってから次へ進みます
4. 非同期処理では、結果を待たずに別の処理へ進めます
5. 時間のかかる処理では、非同期が有効な場合があります
6. Webhookは、出来事が起きた側から通知する仕組みです
7. 例えば、決済完了後に通知を送ることができます
8. 通知を受けるURLを、事前に登録します
9. Webhookは、同じ通知が複数回来る可能性も考えます
10. そのため、受信側には冪等性が重要です
11. Queueは、処理要求を一時的にためる仕組みです
12. 送信側と処理側を、時間的に分離できます
13. Webhookの送信は相手の処理完了を保証しません。
14. 再試行や失敗処理を設計しやすくなります
15. 一方で、処理状況が見えにくくなることがあります
16. 監視とログが、より重要になります
17. 非同期化は、複雑性と引き換えに柔軟性を得る設計です
18. 再送で同じ通知が二度届いても、受付番号とイベントIDで重複を判定します。
19. 順番が入れ替わる場合は時刻だけでなく状態の遷移を確認します。
20. 送信成功と相手の処理完了を同一視しません。
21. イベントIDで重複を見分け、届かなかった通知と順序が逆になった通知を追えるようにします。
