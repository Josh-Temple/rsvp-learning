# 情報資産・依存関係・信頼境界

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

資産台帳を単なる機器一覧にせず、業務価値、データフロー、依存関係、所有者、信頼境界を結び付けて説明できるようにします。

## 本文

1. 守る対象を先に把握します。
2. 資産はデータだけではありません。
3. 業務そのものも資産です。
4. システムも資産です。
5. 端末やサーバーも含みます。
6. Identityも重要な資産です。
7. 認証情報も守る対象です。
8. 鍵やSecretも資産です。
9. 設定情報も資産です。
10. ログも守る対象になります。
11. ソースコードも資産です。
12. ビルド環境も含めます。
13. 外部サービスも依存先です。
14. 委託先も依存関係に入ります。
15. 人の知識も失われ得ます。
16. 資産台帳は一覧だけでは足りません。
17. 所有者を明確にします。
18. 利用目的も記録します。
19. 扱うデータも確認します。
20. 重要度も判断します。
21. 停止時の影響も考えます。
22. 代替手段の有無も見ます。
23. 依存関係をつなげて見ます。
24. 単独で動くシステムは少ないです。
25. 認証基盤へ依存する場合があります。
26. DNSへ依存する場合があります。
27. クラウドへ依存する場合があります。
28. 外部APIへ依存する場合があります。
29. データの流れも確認します。
30. どこで生成されるかを見ます。
31. どこへ保存されるかを見ます。
32. どこへ送信されるかを見ます。
33. 誰が利用するかを見ます。
34. どこで変換されるかも見ます。
35. 信頼境界を意識します。
36. 境界を越える通信を確認します。
37. 組織内でも無条件には信頼しません。
38. 端末間にも境界があります。
39. サービス間にも境界があります。
40. 管理者経路も別に考えます。
41. 本番と開発の境界も重要です。
42. Shadow ITは把握漏れを生みます。
43. 未把握資産は管理しにくいです。
44. 自動検出だけにも頼りません。
45. 業務担当者の知識も使います。
46. 資産はライフサイクルで変わります。
47. 導入時だけでは不十分です。
48. 変更時に台帳を更新します。
49. 廃止時の処理も確認します。
50. データ残存にも注意します。
51. 最重要資産を識別します。
52. すべてを同じ強さで守りません。
53. 業務影響で優先順位を付けます。
54. 単一障害点も確認します。
55. 代替経路も確認します。
56. 依存の集中もリスクになります。
57. 守る対象の理解が対策の前提です。

## 注意

資産の分類方法や重要度尺度は組織ごとに異なります。この章では特定組織の分類基準を固定せず、漏れを減らすための考え方を扱います。
