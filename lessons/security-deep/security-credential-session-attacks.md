# 資格情報・セッションを狙う攻撃

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

資格情報窃取、再利用型の認証攻撃、MFA疲労、セッション窃取を区別し、認証方式、セッション管理、検知、失効を組み合わせて説明できるようにします。

## 本文

1. 攻撃者はパスワードだけを狙いません。
2. 有効なアカウントは強い入口になります。
3. 正規の認証に見える場合があります。
4. 漏えい済み資格情報が使われます。
5. 漏えい資格情報の再利用があります。
6. 他サービスの漏えい情報を試します。
7. 少数候補を多数IDへ試す攻撃もあります。
8. 単純な総当たりとは特徴が違います。
9. フィッシングでも資格情報が盗まれます。
10. マルウェアから盗まれる場合もあります。
11. 端末内の認証情報も狙われます。
12. MFAは重要な防御です。
13. ただし方式によって強さが違います。
14. MFA疲労を狙う攻撃があります。
15. 大量の承認要求で判断を乱します。
16. 利用者が誤承認する場合があります。
17. フィッシング耐性を考えます。
18. 認証成功だけを安全の証明にしません。
19. セッションも狙われます。
20. ログイン後の状態が盗まれる場合があります。
21. セッショントークンが悪用される場合があります。
22. 再認証なしで使われる場合があります。
23. パスワード変更だけでは足りない場合があります。
24. セッション失効が必要になる場合があります。
25. トークン失効も考えます。
26. 端末の侵害も確認します。
27. 新しいMFA登録も監視します。
28. 回復手段の変更も監視します。
29. 認証方式の変更も重要なイベントです。
30. 異常ログインを検知します。
31. 場所だけで決めません。
32. 端末情報も組み合わせます。
33. 時刻や行動も見ます。
34. 権限の強さも考えます。
35. 管理者は特に厳しく守ります。
36. 通常利用と管理利用を分けます。
37. 使われていないアカウントを減らします。
38. 退職や異動で権限を更新します。
39. サービスごとに資格情報を分けます。
40. パスワード再利用を避けます。
41. 漏えい検知も補助になります。
42. アカウント侵害時は広く調べます。
43. メール転送設定も確認します。
44. 新規端末登録も確認します。
45. APIトークンも確認対象です。
46. クラウドのキーも確認します。
47. 侵害範囲をIdentityから追います。
48. 資格情報とセッションを一体で守ります。
49. 認証後も監視を続けます。

## 注意

認証方式の詳細設計はCourse IIIで扱います。この章では攻撃の流れと防御上の意味に重点を置きます。
