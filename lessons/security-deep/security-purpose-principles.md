# セキュリティの目的と基本原則

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

機密性・完全性・可用性だけで終わらず、複数のセキュリティ特性と設計原則を、守る目的と失敗条件から説明できるようにします。

## 本文

1. セキュリティには目的があります。
2. 秘密にするだけではありません。
3. 業務を安全に続けることも目的です。
4. 機密性は閲覧範囲を守ります。
5. 完全性は正しさを守ります。
6. 可用性は必要時の利用を守ります。
7. この三つをCIAと呼びます。
8. ただしCIAだけでは足りません。
9. 真正性も重要な性質です。
10. 本物かどうかを確かめます。
11. 責任追跡性も重要です。
12. 誰が何をしたか追える状態です。
13. 否認防止も扱われます。
14. 行為の否定を難しくします。
15. 信頼性も重要です。
16. 意図した働きを続ける性質です。
17. 性質同士は衝突することがあります。
18. 誰も使えなければ安全ではありません。
19. 利用目的との均衡が必要です。
20. 絶対安全を前提にしません。
21. 残るリスクを管理します。
22. 最小権限は基本原則です。
23. 必要な権限だけを与えます。
24. 権限が強いほど影響も広がります。
25. セキュア・バイ・デザインがあります。
26. 設計段階から安全性を考えます。
27. 後付け対策だけに頼りません。
28. セキュア・バイ・デフォルトも重要です。
29. 初期状態を安全側にします。
30. 利用者任せの設定を減らします。
31. フェイルセキュアも考えます。
32. 故障時の挙動まで設計します。
33. 失敗時に権限を広げません。
34. 攻撃対象領域を減らします。
35. 不要な機能や入口を減らします。
36. 多層防御も基本原則です。
37. 一つの対策だけに依存しません。
38. 失敗を別の対策で補います。
39. ただし製品数が目的ではありません。
40. 役割の違う対策を組み合わせます。
41. 予防だけでは足りません。
42. 検知と対応も必要です。
43. 復旧も設計に含めます。
44. 組織の判断も必要です。
45. 技術だけで完結しません。
46. NIST CSFは六機能で整理します。
47. Governで統治を扱います。
48. Identifyで状況を把握します。
49. Protectで保護を進めます。
50. Detectで異常を見つけます。
51. Respondで影響へ対応します。
52. Recoverで復旧を進めます。
53. 六機能は一方向の手順ではありません。
54. 継続して組み合わせます。
55. 守る目的から原則を選びます。

## 注意

この章は基本原則を扱います。個別の暗号方式、認証方式、製品設定、法令要件は後続章または利用時点の一次資料で確認します。
