# リスク対応・残存リスク・例外管理

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

対策を入れること自体を目的にせず、対応方針、責任者、期限、残存リスク、見直し条件まで含むリスク対応を説明できるようにします。

## 本文

1. 評価したリスクへ対応します。
2. 対応方法は一つではありません。
3. 回避という選択があります。
4. 危険な活動自体をやめます。
5. 低減という選択があります。
6. 可能性や影響を小さくします。
7. 移転や共有もあります。
8. 契約や保険を使う場合があります。
9. ただしリスクは消えません。
10. 責任まで消えるとは限りません。
11. 受容という選択もあります。
12. 何もしないこととは違います。
13. 根拠を持って判断します。
14. リスク所有者を明確にします。
15. 受容権限も明確にします。
16. 重大リスクを現場だけで決めません。
17. 対応案を比較します。
18. 効果を見ます。
19. 費用も見ます。
20. 実現可能性も見ます。
21. 業務への副作用も見ます。
22. 法令や契約も確認します。
23. 依存関係への影響も見ます。
24. 対策で新しいリスクも生じます。
25. 過剰な制限も問題になります。
26. 対応計画を具体化します。
27. 担当者を決めます。
28. 期限を決めます。
29. 必要な資源を決めます。
30. 完了条件を決めます。
31. 証拠も残します。
32. 対策後のリスクを見ます。
33. 残存リスクと呼びます。
34. ゼロになるとは限りません。
35. 残存リスクも再評価します。
36. 許容できるか判断します。
37. 例外管理も必要です。
38. 原則から外れる理由を記録します。
39. 代替策も検討します。
40. 期限のない例外を避けます。
41. 例外に見直し日を置きます。
42. 条件が変われば再承認します。
43. 補完的な管理策も使えます。
44. 同じ効果かを確認します。
45. リスク許容度を意識します。
46. 組織の目的と結び付けます。
47. 全リスクを最低まで下げません。
48. 重要なリスクへ資源を寄せます。
49. 監視条件も決めます。
50. 悪化の兆候を定義します。
51. 対応の効果を確認します。
52. 未完了対策も追跡します。
53. 期限超過もリスクです。
54. 新しい事実で判断を更新します。
55. 事故後は受容判断も見直します。
56. 変更後も残存リスクを見ます。
57. 判断と根拠を追跡可能にします。

## 注意

リスク受容権限、例外承認、リスク許容度は組織ごとに定めます。この章では特定組織の承認経路を固定しません。
