# Firewall・Proxy・WAF・IDS/IPS

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

FirewallやWAFを置けば安全という発想から離れ、対象Protocol、Coverage、暗号化、誤検知、Bypass、運用を説明できるようにします。

## 本文

1. 通信防御は装置名だけで決まりません。
2. 目的と配置を先に確認します。
3. Firewallは通信を制御します。
4. 送信元や宛先を条件にできます。
5. 通信方向とPortも確認します。
6. Stateを見る製品もあります。
7. 端末にも配置できます。
8. クラウドの通信制御もあります。
9. Proxyは通信を仲介します。
10. Forward proxyは利用者側です。
11. Reverse proxyは提供側の前段です。
12. 仲介する通信の範囲を確認します。
13. WAFは主にWeb要求を検査します。
14. HTTPの条件で判断します。
15. WAFはアプリ修正の代替ではありません。
16. IDSは侵入の兆候を検知します。
17. IPSは通信の遮断も扱います。
18. 方式ごとに観測対象は異なります。
19. 暗号化で内容が見えない場合があります。
20. TLSの終端位置を確認します。
21. ログだけで全通信を知れません。
22. 架空の申請APIを考えます。
23. 公開入口にWAFを設置します。
24. 職員が申請を照会します。
25. WAFのルールは稼働しています。
26. しかし閲覧権限の確認が欠けます。
27. WAF稼働だけでは保護できません。
28. API側の認可が必要です。
29. 試験用の他人の申請を用意します。
30. その閲覧要求を安全に試験します。
31. 期待結果はアクセス拒否です。
32. WAFの遮断ログも調べます。
33. アプリ側の拒否記録も調べます。
34. ルール設定と有効性は別です。
35. 入口を通らない経路も探します。
36. 内部から直接接続できる場合があります。
37. 迂回経路があれば効果は限定的です。
38. ネットワーク図を更新します。
39. 許可ルールの所有者を決めます。
40. 不要な許可を整理します。
41. 例外ルールには期限を付けます。
42. 変更前後で通信を検証します。
43. 正常な業務の誤遮断も見ます。
44. 誤検知も見逃しもあります。
45. 警告を確認する担当を決めます。
46. 保存するログの範囲も設計します。
47. ログ欠損時は結論を保留します。
48. 障害時の通過動作を確認します。
49. Fail openは常に許容できません。
50. 装置停止時の業務影響も考えます。
51. 管理画面と設定Backupを守ります。
52. 更新と権限管理も必要です。
53. 事前の設定確認だけで終えません。
54. 模擬要求で防御動作を確かめます。
55. 構成変更後には再検証します。
56. 最後に残る脆弱性を記録します。

## 注意

架空の申請APIの例です。Firewall/Proxy/WAF/IDS/IPSの機能は製品・配置・設定で異なり、TLS終端位置やバイパス経路も評価対象です。NIST SP 800-41 Rev.1とSP 800-94は古い技術ガイドであり、最新製品の固有仕様を保証しません。
