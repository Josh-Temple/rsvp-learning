# C2・持ち出し・痕跡

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

暗号化通信や正規サービスの利用だけで安全と判断せず、通信先、頻度、データ量、端末行動、権限変化を組み合わせて侵害後の活動を評価できるようにします。

## 本文

1. C2は外部制御用の通信です。
2. 侵害端末を外部から制御します。
3. 命令を受け取る場合があります。
4. 結果を返す場合もあります。
5. 正規の通信方式が使われる場合があります。
6. 暗号化通信が使われる場合もあります。
7. 暗号化されているだけでは安全と限りません。
8. 正規クラウドが悪用される場合もあります。
9. 通信先の評判だけでは判断しません。
10. 通信の頻度も見ます。
11. 時間帯も見ます。
12. 端末の役割も見ます。
13. 通信量も見ます。
14. プロセスの行動も見ます。
15. 情報収集の段階があります。
16. 端末内の情報を集める場合があります。
17. 共有領域から集める場合もあります。
18. メールやクラウド情報も対象になります。
19. 持ち出し前にまとめる場合があります。
20. 外部への情報持ち出しがあります。
21. 一度に大量とは限りません。
22. 少量を分ける場合もあります。
23. 通常通信に混ざる場合もあります。
24. 出口制御が重要です。
25. 必要な外向き通信を把握します。
26. 不要な外向き通信を減らします。
27. プロキシログも観測に使えます。
28. DNSログも手掛かりになります。
29. クラウド監査ログも重要です。
30. Identityログも組み合わせます。
31. 隠蔽を狙う行動があります。
32. 正常に見せようとする場合があります。
33. 痕跡を減らそうとする場合もあります。
34. 防御機能を弱める行動もあります。
35. ログ収集を妨げる場合があります。
36. セキュリティ機能を止める場合もあります。
37. 監視設定の変更も重要です。
38. ログ欠損自体が兆候になる場合があります。
39. 正常基準を持つことが重要です。
40. 端末ごとに通常通信は違います。
41. サーバーと利用端末も違います。
42. 単一指標だけで断定しません。
43. 複数の弱い兆候を結びます。
44. C2遮断だけで調査を終えません。
45. 関連アカウントも封じ込めます。
46. 持ち出し対象を確認します。
47. 他端末への到達も確認します。
48. 証拠を保全します。
49. 影響と目的を見極めます。
50. 侵害後の観測点を事前に設計します。

## 注意

検知回避や情報持ち出しを成功させる具体的手順は扱いません。防御側が観測すべき行動と封じ込めを中心に扱います。
