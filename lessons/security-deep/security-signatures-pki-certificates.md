# デジタル署名・PKI・証明書

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

署名と暗号化を区別し、証明書が「公開鍵と主体の結び付き」をどのように信頼させるか説明できるようにします。

## 本文

1. デジタル署名は暗号化とは別です。
2. 主な目的は真正性と完全性です。
3. 署名者の秘密鍵を使います。
4. 検証には公開鍵を使います。
5. Data変更を検出できます。
6. 署名者との結び付きも必要です。
7. 公開鍵だけでは主体を保証しません。
8. PKIが信頼を支えます。
9. 証明書を使います。
10. 証明書は公開鍵情報を含みます。
11. 主体情報も含みます。
12. 発行者情報も含みます。
13. 有効期間もあります。
14. 利用目的も制約されます。
15. CAが証明書を発行します。
16. Root CAがあります。
17. Intermediate CAもあります。
18. Trust chainを検証します。
19. Rootの信頼が前提になります。
20. 信頼Storeを管理します。
21. 証明書署名を検証します。
22. 有効期限を確認します。
23. 名前の一致も確認します。
24. 用途も確認します。
25. 失効状態も考慮します。
26. 秘密鍵漏えいは重大です。
27. 証明書だけ交換して終わりません。
28. 侵害した鍵を無効化します。
29. 新しい鍵を生成します。
30. 依存先も更新します。
31. TLSでも証明書を使います。
32. Server認証に利用します。
33. Client証明書も使えます。
34. 暗号化だけがTLSの役割ではありません。
35. 相手の確認も重要です。
36. 証明書警告を無視しません。
37. 検証無効化は信頼を壊します。
38. Code signingにも署名を使います。
39. Softwareの出所確認に役立ちます。
40. 署名済みでも安全とは限りません。
41. 署名者が侵害される場合があります。
42. 署名対象の品質も別問題です。
43. Timestampも利用されます。
44. 署名時点を扱う仕組みがあります。
45. 鍵保護が中心課題です。
46. Hardware保護を使う場合があります。
47. 発行権限も厳しく管理します。
48. 証明書台帳を持ちます。
49. 期限切れを監視します。
50. PKIを信頼Lifecycleとして運用します。

## 注意

証明書発行やTLS設定の具体値は利用環境の現行標準を確認します。警告回避や検証無効化を安全策として扱いません。
