# 脅威・脆弱性・露出・攻撃対象領域

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

「脆弱性があるから危険」と一括りにせず、誰が、何を利用し、どの経路から、何へ影響を与えるのかを分解して説明できるようにします。

## 本文

1. 脅威と脆弱性を分けて考えます。
2. 脅威は損害の原因になり得ます。
3. 脅威主体は行為者を指します。
4. 外部攻撃者だけではありません。
5. 内部者も脅威主体になり得ます。
6. 事故や災害は主体を持ちません。
7. 脅威事象として扱えます。
8. 脆弱性は利用され得る弱点です。
9. ソフトの欠陥だけではありません。
10. 設定ミスも脆弱性になります。
11. 過剰権限も弱点になります。
12. 運用不備も弱点になります。
13. 人的な弱さも考えます。
14. 露出は到達可能性に関係します。
15. 弱点が外部へ見える場合があります。
16. 内部だけから届く場合もあります。
17. 到達条件で危険度は変わります。
18. 攻撃ベクトルは侵入経路です。
19. メールが経路になる場合があります。
20. Webが経路になる場合があります。
21. 認証情報が経路になる場合もあります。
22. 供給網も経路になり得ます。
23. 攻撃対象領域を把握します。
24. 公開サービスだけではありません。
25. 管理画面も入口になります。
26. APIも入口になります。
27. クラウド設定も対象です。
28. CI/CDも攻撃対象です。
29. 委託先もつながっています。
30. 不要な入口は減らします。
31. 攻撃対象領域は変化します。
32. 新機能で入口が増えます。
33. 新しい委託先でも変わります。
34. 公開設定の変更でも変わります。
35. ゼロデイも考慮します。
36. 未知の弱点は完全には防げません。
37. 既知脆弱性だけを見ません。
38. 設計上の弱点もあります。
39. OWASPは代表的な分類を示します。
40. 分類は完全な一覧ではありません。
41. アクセス制御の不備も重要です。
42. 設定不備も重要です。
43. 供給網の不備も扱われます。
44. Injectionも代表例です。
45. 安全性を欠く設計もあります。
46. 攻撃しやすさを評価します。
47. 成功時の影響も分けて見ます。
48. 既存対策も評価に含めます。
49. 検知できるかも重要です。
50. 復旧できるかも重要です。
51. 一つの用語だけで結論を出しません。
52. 脅威シナリオへ具体化します。
53. 誰が何を狙うかを考えます。
54. どの弱点を使うかを考えます。
55. どこから到達するかを考えます。
56. 何が起きるかを考えます。
57. 分解すると対策を選びやすくなります。

## 注意

この章では攻撃概念を防御判断のために扱います。実環境への侵入手順や、許可のない検証方法は扱いません。
