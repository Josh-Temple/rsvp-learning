# リスクアセスメント

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

スコアを機械的に付けるのではなく、評価の前提、根拠、不確実性を示しながら、優先順位を説明できるようにします。

## 本文

1. リスク評価には範囲が必要です。
2. 何を評価するかを決めます。
3. 対象業務を明確にします。
4. 対象システムも明確にします。
5. 時間軸も確認します。
6. 評価基準を先に決めます。
7. 後から都合よく変えません。
8. 資産と依存関係を確認します。
9. 脅威シナリオを作ります。
10. 脆弱性や露出も確認します。
11. 既存対策も洗い出します。
12. 発生可能性を考えます。
13. 頻度だけでは決まりません。
14. 攻撃者の能力も関係します。
15. 到達しやすさも関係します。
16. 必要条件の多さも関係します。
17. 影響も別に評価します。
18. 金銭損失だけではありません。
19. 業務停止も影響です。
20. 個人への影響もあります。
21. 信用低下も考えます。
22. 法務上の影響もあり得ます。
23. 安全への影響も考えます。
24. 波及範囲も確認します。
25. 一つの尺度に無理にまとめません。
26. 定性的評価があります。
27. 低中高などで整理できます。
28. 比較しやすい利点があります。
29. 境界が曖昧になる弱点もあります。
30. 定量的評価もあります。
31. 金額や頻度を使う場合があります。
32. 入力値の品質が重要です。
33. 推定値には幅があります。
34. 小数点で精密に見せません。
35. リスクマトリックスも使われます。
36. 便利ですが限界があります。
37. 同じ色でも状況は違います。
38. 順序が変わる場合もあります。
39. 複数手法を組み合わせます。
40. 根拠を記録します。
41. 仮定も記録します。
42. 不確実性も記録します。
43. データ不足を隠しません。
44. 最悪条件だけにも寄りません。
45. 平均だけにも寄りません。
46. 極端な影響も検討します。
47. 既存対策の有効性を確認します。
48. 存在だけでは十分ではありません。
49. 設定や運用を確かめます。
50. 検知能力も評価します。
51. 復旧能力も評価します。
52. リスク所有者を明確にします。
53. 判断する責任者が必要です。
54. 優先順位を説明できる形にします。
55. 重大変更後は再評価します。
56. 事故後にも見直します。
57. 新しい脅威でも見直します。
58. 評価は一度きりではありません。

## 注意

具体的な評価尺度や受容基準は組織によって異なります。数値モデルを使う場合も、精度やデータ品質を確認し、見かけの正確さを避けます。
