# 通信経路とセキュリティ境界

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

ネットワーク図を機器一覧ではなくData flowと信頼境界として読み、保護・観測・失敗時の影響を説明できるようにします。

## 本文

1. 通信は一つの線ではありません。
2. 名前解決から始まる場合があります。
3. Routeを通って相手へ届きます。
4. Gatewayを通る場合があります。
5. Proxyを通る場合もあります。
6. Load balancerも経路になります。
7. CDNが入る場合もあります。
8. Applicationへ到達します。
9. Databaseへ進む場合もあります。
10. 外部APIへ出る場合もあります。
11. Data flowを描きます。
12. 送信元を確認します。
13. 送信先を確認します。
14. Protocolを確認します。
15. Portも確認します。
16. Dataの種類も確認します。
17. 認証情報の流れも確認します。
18. 管理通信は別に考えます。
19. 監視通信も別経路の場合があります。
20. 信頼境界を示します。
21. Internet境界だけではありません。
22. 利用者とServiceにも境界があります。
23. Service間にも境界があります。
24. Cloud account間にもあります。
25. 管理面とData面も分けます。
26. 暗黙の信頼を減らします。
27. Network位置だけで信じません。
28. Identityと端末状態も使います。
29. 経路上の保護を考えます。
30. 暗号化が必要な場所を確認します。
31. 認証が必要な場所を確認します。
32. 認可も必要です。
33. 観測点を設計します。
34. DNS logがあります。
35. Proxy logがあります。
36. Firewall logがあります。
37. Application logもあります。
38. Cloud audit logもあります。
39. 全てを集めるだけでは足りません。
40. 重要な判断に使える形にします。
41. 失敗経路も考えます。
42. DNS障害があります。
43. Identity障害があります。
44. Gateway障害もあります。
45. 外部API障害もあります。
46. 代替経路の安全性も見ます。
47. Bypass経路を残さないようにします。
48. 実際の通信と図を比較します。
49. 変更時にData flowを更新します。
50. 経路理解が防御設計の前提です。

## 注意

具体的なNetwork構成は環境ごとに異なります。構成図と実際のRoute、Cloud設定、外部Service依存を突き合わせて確認します。
