# MITRE ATT&CKと攻撃シナリオ

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

ATT&CKの項目数を埋めることを目的にせず、観測した行動を分類し、検知Coverageと対策の穴を説明するために使えるようにします。

## 本文

1. ATT&CKは攻撃行動の知識ベースです。
2. 組織間の共通言語になります。
3. tacticは攻撃者の目的を表します。
4. techniqueは行動の方法です。
5. sub-techniqueは細分化した方法です。
6. 項目名は攻撃順序を定めません。
7. 全ての段階が現れるとは限りません。
8. Enterpriseと他領域を区別します。
9. 環境ごとに適用範囲が違います。
10. 架空の行政サービスを考えます。
11. 職員に偽の通知が届きます。
12. 職員は不審メールを報告します。
13. これだけでは侵害は未確定です。
14. 次に異常なログインを想定します。
15. 正規アカウントの悪用を疑います。
16. Valid Accountsが分類候補です。
17. 成功ログだけで断定しません。
18. 通常の勤務や端末を照合します。
19. 新しい権限付与も観測します。
20. 権限変更の記録を確認します。
21. 異常な探索行動も調べます。
22. Discoveryとの関係を考えます。
23. 別サービスへのアクセスも調べます。
24. Lateral Movementも候補です。
25. 外部への転送量を確認します。
26. Exfiltrationの可能性を考えます。
27. 通常の連携通信かもしれません。
28. 分類と攻撃確定は別の作業です。
29. 複数の証拠を時系列で結びます。
30. メール報告と認証ログを照合します。
31. 端末とクラウドの記録も使います。
32. 観測不能な区間を明記します。
33. データの未収集は無事の証拠ではありません。
34. 各行動に予防策を対応させます。
35. 各行動に検知方法も対応させます。
36. 封じ込めの判断条件を整理します。
37. 失効すべき認証情報を確認します。
38. 担当者が判断を記録します。
39. 仮説に反する証拠も探します。
40. 分類済みなら検知済みとは限りません。
41. 検知ルール数は網羅率ではありません。
42. 対象ログが届くか確かめます。
43. 模擬イベントで警告を確認します。
44. 検知までの遅れも記録します。
45. 誤検知の理由も調べます。
46. 観測点が欠ければ限界を示します。
47. 新しい行動を脅威情報で確認します。
48. ATT&CKはリスク得点表ではありません。
49. 資産と業務影響を別に評価します。
50. 組織に重要な行動を優先します。
51. 手法一覧を埋めても安全ではありません。
52. 模擬ケースの条件を変更します。
53. 対象が端末からSaaSへ変わります。
54. 必要なログや検知点も変わります。
55. 攻撃の再現ではなく防御を検証します。
56. 学んだ欠落を改善計画へ戻します。

## 注意

このシナリオは架空です。ATT&CKの項目は実行順序、個別事案の攻撃確定、検知の有効性、組織固有のリスク順位を自動で保証しません。分類はMITRE Enterprise Matrixの対象環境に照らして再点検します。
