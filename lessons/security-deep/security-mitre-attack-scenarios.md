# MITRE ATT&CKと攻撃シナリオ

Status: COMPLETE v0.1
Created: 2026-10-08

## 学習目標

ATT&CKの項目数を埋めることを目的にせず、観測した行動を分類し、検知Coverageと対策の穴を説明するために使えるようにします。

## 本文

1. ATT&CKは攻撃行動の知識ベースです。
2. 共通言語として使えます。
3. tacticは攻撃者の目的です。
4. techniqueは目的を達成する方法です。
5. sub-techniqueもあります。
6. tacticは固定手順ではありません。
7. 全攻撃が同じ順序では進みません。
8. 全tacticが必ず現れるわけでもありません。
9. 偵察があります。
10. 攻撃用資源の準備があります。
11. 初期アクセスがあります。
12. 実行があります。
13. 永続化があります。
14. 権限昇格があります。
15. 隠蔽があります。
16. 防御機能の弱体化があります。
17. 資格情報へのアクセスがあります。
18. 環境把握があります。
19. 横展開があります。
20. 情報収集があります。
21. 外部制御があります。
22. 情報持ち出しがあります。
23. 影響を与える段階があります。
24. 分類は観測整理に使います。
25. 攻撃を再現する目的ではありません。
26. 仮想シナリオで考えます。
27. 職員へのフィッシングを想定します。
28. 資格情報が盗まれたとします。
29. 有効なアカウントとして使われます。
30. 環境を調べる場合があります。
31. 高権限を狙う場合があります。
32. 別サービスへ移る場合があります。
33. 情報を集めます。
34. 外部へ持ち出す場合があります。
35. 最後に影響が出る場合があります。
36. ただし別の流れもあります。
37. 途中で検知できる点を探します。
38. メール報告が一つの観測点です。
39. Identityログも観測点です。
40. 端末ログも観測点です。
41. ネットワークログも観測点です。
42. クラウド監査ログも使います。
43. 行動ごとにCoverageを見ます。
44. 検知ルールの数だけで判断しません。
45. 重要シナリオを覆うか確認します。
46. 管理策との対応も見ます。
47. 予防できる点を探します。
48. 検知できる点を探します。
49. 封じ込めできる点も探します。
50. 復旧できる点も考えます。
51. ATT&CKだけでリスク順位を決めません。
52. 資産と影響をCourse Iで評価します。
53. 業界や環境で重要行動は変わります。
54. 自組織に関係する行動を選びます。
55. 脅威情報で更新します。
56. インシデントからも更新します。
57. 演習で検知Coverageを確かめます。
58. 未観測領域を記録します。
59. ATT&CKを防御改善へつなげます。

## 注意

ATT&CKは脅威行動の知識ベースであり、組織固有のリスクを自動的に決めるフレームワークではありません。Course Iのリスク評価と組み合わせて使います。
